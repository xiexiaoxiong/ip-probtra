# 专利无效检索工作流规范

> 状态：强制执行  
> 版本：3.65  
> 生效日期：2026-08-20  
> 上位规则：`PROJECT_CHARTER.md` 2.40  
> 适用范围：`5-invalidity-search-test` 唯一无效后端、Portal Agent、十一模块实验室和共享中立解析接入

## 1. 目的与权威关系

本文件把项目宪章中的模块边界、日期规则和多轮检索原则落实为可实现、可测试、可重放的状态机。它不改变法域或法律边界；如与 `PROJECT_CHARTER.md` 冲突，以宪章为准并先修正文档，禁止由代码静默选择解释。

在无效检索及其共享接入范围内，本文件优先于根级和模块级 `AGENTS.md` 决定业务状态机、模块契约和持久化不变量；`AGENTS.md` 继续决定仓库工程事实、运行方式和更严格的局部约束。两者出现跨作用域歧义时必须先修正文档，不允许实现自行挑选较宽松解释。

原侵权分析的“模块一到模块四单向链路”只适用于商品侵权流程。无效检索允许 `I0` 依据持久化结果创建后续轮次，但任何模块不得在进程内递归调用自己或下一轮。

Agent 与十一模块实验室只是同一业务的两种前端操作方式：前者自动推进完整流程，后者允许逐模块查看输入输出。两者必须调用同一个服务实例、同一 schema、同一规则版本和同一证据状态机。`test`、5209 与 `invalidity_test` 作为历史运行标识暂时保留，不再表示另一个测试业务后端；历史 5109/release 只作迁移审计，不接受新用户请求。

### 1.1 不是两份并列主文件

`PROJECT_CHARTER.md` 是仓库唯一的产品总纲；根目录和模块目录中的 `AGENTS.md` 是工程协作索引与局部实现约束，不是另一份产品定义。两者都要求预读，是因为作用不同，不代表可以在冲突时任选其一。

- 只涉及原侵权分析的行为，继续按根级和对应模块级 `AGENTS.md` 处理。
- 涉及无效检索的法律边界、证据标准和产品范围，按宪章处理；涉及本系统状态机、轮次和数据契约，按本规范处理。
- 修改共享解析、Portal、数据库或运维边界时，必须同时满足原系统的不回归要求和无效系统的隔离要求；不能满足时停止修改并先修正文档或拆分实现。
- README、会话日志和代码现状只能说明运行事实，不能反向覆盖宪章或本规范。

因此，新增无效检索规则不得继续写进原侵权模块的业务说明并形成第二套总规则；这里只维护一份可由测试版和正式 release 共同哈希、共同重放的无效工作流规范。

## 2. 基本分析单位

### 2.1 调查层级

```text
Investigation（一次上传/一次运行）
  -> ClaimInvestigation（当前阶段每项独立权利要求一个独立循环）
       -> Initial Iteration（固定五类首轮，不计入 gap 轮次）
       -> Gap Iteration 1
       -> Gap Iteration 2
       -> Gap Iteration 3
       -> Gap Iteration 4
       -> Gap Iteration 5
       -> 组合分析与大 Claim Chart
```

- 文献文件和来源快照可以在同一 Investigation 内共享。
- 模块一快照继续包含完整的独立和从属权利要求、依赖关系及原文。
- 当前阶段只为 `claim_type=INDEPENDENT` 的权利要求创建 ClaimInvestigation；关键日、资格、单文献覆盖、D1、gap、组合分析和停止状态必须按独立权利要求保存。
- 一项独立权利要求停止不得终止其他独立权利要求。
- 从属权利要求不创建调查、不进入自动检索/分析、状态汇总、人工确认计数或报告结论。未来恢复该范围必须升级宪章和本规范。
- 没有识别到独立权利要求时必须失败关闭并要求修正解析，禁止回退处理全部权利要求。
- 历史版本已经存在的从属 ClaimInvestigation 不得改写；新版读取契约必须标记为 `in_scope=false`，并从当前汇总中排除。

### 2.2 不可变输入

创建 Investigation 时必须冻结：

- 原始输入文件或合规快照、字节数和 SHA-256；
- 中立解析输出、解析器版本和来源哈希；
- 目标专利元数据、完整权利要求、依赖关系、说明书和目标附图；
- 用户声明的申请日、优先权、目标公开日及其确认状态；
- provider 范围、模型、规则版本、最大自动轮次和预算。

模块一重跑不得改变既有 Investigation 的输入。重跑必须创建新的 Investigation 或显式的新输入版本。

## 3. 状态机

### 3.1 Investigation 状态

允许状态：

- `created`
- `queued`
- `running`
- `needs_human_review`
- `partial`
- `completed`
- `failed`
- `cancelled`

所有终态都必须写入 `completed_at`；`needs_human_review` 可以是当前自动运行的终态，但保留 checkpoint，用户确认后创建新的继续作业。

### 3.2 ClaimInvestigation 状态

```text
critical_date_review
  -> initial_search
  -> single_reference_review
     -> novelty_evidence_complete                         [单篇完整覆盖]
     -> closest_prior_art_selected                       [无单篇完整覆盖]
        -> obviousness_precheck                          [先分析 D1 启示、惯用手段、动机、反向教导和效果]
           -> combination_review                         [无需新增检索或仅待律师确认]
           -> gap_search                                 [仅检索预分析尚未解决的补证目标]
              -> single_reference_review                 [候选、取文、日期、I4-S 后重查]
           -> combination_review                         [五轮用尽后仍有 gap，也继续形成大 CC]
```

任意非终态还可以进入：

- `needs_human_review`
- `search_budget_exhausted`
- `partial`
- `failed`
- `cancelled`

`novelty_evidence_complete` 和 `inventive_step_evidence_complete` 都是当前 ClaimInvestigation 的成功终态，必须直接生成对应报告，不得再被普通“继续检索”操作重开。若未来需要对成功终态补充更多证据，应另建具有 `supplements_claim_investigation_id` 关联的新调查；该能力不属于当前普通 continuation 契约，也不得覆盖原停止结果。

### 3.3 状态转换不变量

1. 没有已确认关键日时不得进入正式检索。
2. 没有取得真实内容并完成日期资格时不得创建实质 CC 披露结论。
3. 每篇新文献必须先进入单文献比对，才能进入 D1 或组合候选。
4. 一篇合格文献完整覆盖全部限制时，必须优先进入新颖性停止分支。
5. 没有单篇完整覆盖时才允许选择 D1 和运行创造性组合分析。
6. 下一轮只能在上一轮所有 query、module run、job 和 iteration 已收口后创建。
7. 状态转换、人工决定和重试都必须写审计事件；旧 worker 的过期租约不得覆盖新状态。

### 3.4 I4-S 多文献批次与 worker 并发

律师模块六提交多份 `analysis_ready` 文献时，Portal 必须先创建持久化批次，并为每份文献保存
`document_id`、当前 `module_run_id`、重试谱系和逐篇状态。批次查询每次都返回当前已完成、
排队、执行、失败和已有可用 disclosure 的文献数，并立即返回每篇现有输出；不得等待全部
Promise 一次性完成后才把结果交给业务页面。浏览器刷新、断网或等待上限只影响当前轮询，不能
取消后端作业、把仍在运行的批次标成失败，或者清空已经完成的单篇结果。历史上未通过批次入口
创建的 I4-S 不得按固定时间间隔猜测批次；应以同案、同独立权利要求最新 I3_FETCH 共享的
`candidate_filter_run_id` 为权威血缘，只纳入 `analysis_ready=true` 且正文与内容哈希完整的
文献。该清单中已有 I4-S 的文献复用最新 run，尚未创建 I4-S 的文献补建独立 run；资源归属
仍须核验。没有持久化筛选血缘的更早历史数据才允许使用时间连续性作为兼容兜底。

`queued` 的等待时间从 run/job 创建至 `started_at`，执行时间从 `started_at` 至终态时间；两者
必须分开展示。批次只有在全部单篇任务进入终态后才能进入 `completed`、`partial` 或 `failed`，
其中已有可用逐项结果但整体结构复核或部分特征失败的文献仍以 partial 逐篇展示并按既有规则
有限重试。模块六批次只创建 `I4_S_SINGLE_REFERENCE`，不得自动创建
`I4_C_CLOSEST_PRIOR_ART` 或 `I4_I_INVENTIVE_STEP`。

测试 5209 在单进程内启动多个 `DurableWorker` 实例并共享 PostgreSQL 队列；每个实例使用独立
`worker_id`，通过 `FOR UPDATE SKIP LOCKED` 和租约 CAS 领取不同 job。默认并发为 2，
`INVALIDITY_WORKER_CONCURRENCY` 允许 1—4；停机时共享 stop event，但每个仍在处理任务的
worker 必须分别释放自己的活动租约。传入测试替身 worker 时保持单 worker，避免测试注入被
隐式复制。

### 3.5 模块三画像生成的输出完整性与审计

`I2_INVENTIVE_PROFILE` 必须获得足以完整返回权利要求拆解、机构模型和发明画像的输出预算，
不得继续以短检索式生成的预算截断画像。模型响应必须在结构化解析前保留原始内容、模型、
`finish_reason`、字符数、输出预算和尝试序号；解析失败时同样冻结审计工件。若响应因长度上限
或非法 JSON 未形成完整对象，模块内部只允许携带“压缩重复表述并完整闭合 JSON”的反馈重新
生成一次，不得复用部分 JSON、猜补缺失技术事实或把该错误归类为网络不可用。第二次仍失败时
分别以 `GLM_OUTPUT_TRUNCATED` 或 `GLM_OUTPUT_INVALID_JSON` 收口，并保留两次响应谱系。

模块三必须把“可逐项比对的底层技术特征”与“用于检索的核心发明点”分层保存：`features`
和 `mechanism_model` 继续完整保存构件、连接、位置、导向、限位、驱动及其他可回溯细节；
`inventive_point_features` 只保存检索级核心发明点。候选核心发明点只有 1—2 项时保持原数量，
不超过 3 项且技术目的、作用链或效果彼此独立时可以分别保留；候选超过 3 项时，模型必须按
共同技术目的或同一机构作用链归并为 1—3 项上位技术能力/关键状态变化。每个归并项的
`feature_ids` 必须覆盖该组全部底层特征，不能靠截断丢弃绑定；原始细节继续在普通视图的对应
特征清单和技术审计中展示。不得为凑数量合并彼此独立的技术构思，也不得使用“结构改进”、
“性能提升”等无技术内容的空泛概括。最能代表整项发明的检索级发明点排在第一位，供首轮固定
五线使用。模型返回超过 3 项时必须以明确验证原因有界重生一次，禁止代码静默裁掉第 4 项以后
的事实或自行编造上位概念。

## 4. 关键日与候选日期通道

### 4.1 专利级关键日

关键日按整件专利确定一次，当前自动调查只应用于独立权利要求（宪章 2026-07-25 决定）：

1. 专利存在可解析优先权日时，使用最早优先权日作为整件专利的关键日；
2. 无可解析优先权日时使用申请日；
3. 模块一快照中的全部权利要求保留同一专利级日期事实；只为范围内的独立权利要求逐条写入关键日和依据（`critical_date_basis`），不再逐项停车等待人工填写或核验；
4. 仅当专利级申请日和优先权日均缺失或无法解析时，才进入 `critical_date_review` / `needs_human_review`；
5. 用户仍可通过人工复核为整件专利改定关键日（确认优先权、使用申请日或手工日期），改定结果适用于全部范围内的独立权利要求；
6. 多优先权、逐主题分别确定关键日的精细化规则当前不启用，留待用户明确恢复。

`critical_date_review` 是当前持久化契约的规范状态名；Portal 可以只为读取旧记录兼容
`awaiting_critical_date`，但新记录、API 和报告不得继续产生该旧别名。

Portal 必须显示当前使用的专利级关键日及其依据；仅在专利级日期缺失进入待人工复核时，显示候选日期、来源和冲突原因，并允许用户确认后从 checkpoint 继续；不得要求重新上传才能继续。

### 4.2 两条专利发现通道

#### A. 普通现有技术通道

- provider 查询以公开日在关键日前为召回边界；
- 本地规则再次核验公开日期和公众可得性；
- 合格材料可以进入新颖性与创造性分析。

#### B. 中国抵触申请候选通道

- 单独检索更早申请/优先权事实、关键日后公开且符合用户确认的目标公开日前窗口的中国专利申请；
- provider 必须返回申请/优先权日、公开日和公开编号，不能只按关键日前公开过滤；
- 本地规则按具体权利要求判定；
- 合格候选只进入新颖性路径，不进入创造性组合。

两条结果按稳定标识、同族和内容哈希去重，但保留各自 query lineage。provider 过滤不产生法律资格结论。

### 4.2.1 I3-P provider 能力、执行与降级契约

I3-P 不再把“一个 provider 名称”理解为检索、书目核验、全文、PDF、附图和专利族的全能
承诺。每个 adapter 必须声明并在 module run 中保存以下 capability：

- `discovery`
- `bibliographic_verification`
- `full_text`
- `pdf`
- `images`
- `family`
- `publication_date`、`filing_date`、`priority_date`

MVP 的 provider 分工如下：

1. `patsnap` 是当前用户指定的全球专利主 provider 候选。它的 adapter 必须先根据用户提供
   的接口文档冻结认证、查询、分页、字段映射、原始响应、限流和许可边界；只有真实样本
   验收后才能声明具备相应 discovery、书目、全文、PDF、图片、族或日期能力。未提供文档
   或凭据时必须 fail closed，不能伪造 Patsnap 响应或回落正式环境凭据。
2. 自动化专利候选检索不回落 `epo_ops`、USPTO 或 `google_patents`。智慧芽 P002 返回
   具有可规范化公开号/申请号的 lead 后，I3-E 必须先把同一候选交给 `epo_ops` 做官方书目
   核验和全文/PDF/页面补取；这属于取文 provider chaining，不是候选检索回退。EPO 不得
   接收 I2 检索式或改变智慧芽候选集合。EPO 对同一文献正常收口并明确
   `not_found`、`no_coverage` 或 `media_unavailable` 时，才允许以 P002 冻结的同一
   `patent_id + pn` 调用智慧芽 P020 补取 PDF；P020 仍不得增加或替换候选。
   Google Patents、公开网页和浏览器自动化仍可按根宪章用于人工补充发现或取文，但必须
   记录实际来源，且链接和摘要始终只是 `lead`，不能冒充智慧芽执行结果。
3. Yahoo 等公开网页 fallback 的批次固定 `complete=false`，`actual_provider` 必须显示
   实际发现源；即使后来取得某篇真实文件，也不能把一次网页检索冒充为完整 provider 执行。
4. WIPO、USPTO 或相应国家/地区局可以补取/核验官方文件；人工导入继续是一等路径。

EPO OPS 取文仅允许在当前环境显式配置的情况下启动：测试使用
`INVALIDITY_TEST_EPO_OPS_KEY` / `INVALIDITY_TEST_EPO_OPS_SECRET`，正式使用
`INVALIDITY_PROD_EPO_OPS_KEY` / `INVALIDITY_PROD_EPO_OPS_SECRET`。经用户或运维人员显式授权，
同一组外部凭据值可以分别写入这两套变量及其权限文件；运行时仍不得读取另一环境变量或以其为
fallback。任一当前环境变量缺失、OAuth 失败或 provider 名称未批准时必须 fail closed。access token、
Basic/Bearer 头和密钥不得进入数据库、普通日志、前端或报告。

Patsnap lead 到 EPO 文献的映射必须遵守：

1. 优先规范化并使用智慧芽返回的 publication number（国家代码 + 数字 + kind code）；
2. 只有 publication number 缺失时才可使用 application number 请求 EPO 解析 publication
   reference，解析结果仍须与智慧芽 lead 的国家、号码和可得 kind code 对应；
3. EPO biblio 返回的 publication reference 必须与目标公开号精确对应；同族文献、相似题名
   或检索结果不能替代同一文献；
4. OAuth、biblio、fulltext inquiry、description/claims、images/PDF 页面每次请求分别记录
   脱敏状态、响应哈希、媒体类型和限流信息；token 与鉴权头不落库；
5. 全文目录或媒体链接本身仍是 lead。只有实际响应字节通过 MIME、文献标识和大小校验并
   冻结 SHA-256 后，才生成 `retrieved_document`。
6. P020 fallback 只接受 EPO 已正常完成的无覆盖/无媒体终态，或 EPO 对该精确 publication
   reference 返回可核验的 `404 not_found`。OAuth/鉴权、网络/超时、限流、5xx、响应解析、
   申请号多义或身份不一致均不得触发 P020；这些故障必须原样收口，不得被 fallback 掩盖。
7. P020 请求必须使用 P002 lead 的同一 `patent_id`，并要求返回 `pn` 与原候选规范化后精确
   一致、`replace_by_related=0`、`pn_related` 为空。临时 PDF 地址只有实际下载、PDF 文件
   签名、MIME、大小、可解析性、原始字节冻结和 SHA-256 通过后才成为
   `retrieved_document`。P020 失败则保留 lead/evidence gap。
8. provenance 必须分别保存 `discovery_provider=patsnap`、有序 `retrieval_attempts`、
   EPO 的身份/无覆盖状态、P020 的同文献身份状态和最终 `retrieval_provider`。最终取文源
   为 P020 时使用 `patsnap_p020`，不得覆盖 EPO 的前一次尝试记录。

普通现有技术通道和中国抵触申请通道必须各自生成 provider 可表达的日期/国家范围，同时把
“provider 召回过滤”与“本地法律资格”分别保存。provider 无法表达申请/优先权日期窗口时，
允许明确检索一个不会漏掉目标范围的超集，再用冻结的申请/优先权日期在本地确定性过滤，并
记录 `local_superset_filter`；这不等同于检索失败。若 provider 缺少本地过滤所需日期字段、
静默缩窄召回范围，或把该通道改成全球无日期网页搜索，则该查询必须 `partial` 或切换到已
批准的 provider。只有实际执行的必要能力均成功、所有失败均已解释、且本地日期引擎再次
核验后，SearchBatch 才能 `complete=true`。

### 4.2.2 智慧芽 P002 字段化查询编译与零命中处理

智慧芽是当前自动化专利候选发现的默认 provider。I2 仍负责结合权利要求和目标附图生成
保护客体/类别、类别共有技术语境、发明点区别特征及中英文术语；进入 P002 前必须再经过
确定性编译和守门：

1. I2 必须先保存一份 `invention_search_profile`，至少包括：
   - `protected_subject`：独立权利要求保护的客体/类别及中英文同义词；
   - `classification_anchors`：IPC/CPC 等分类锚点，并逐项标明 `parsed_fact` 或
     `model_suggested` 来源；模型建议只用于检索，不回写为模块一著录事实或证据；
   - `common_context_features`：该类别通常具有、用于确认同类技术语境的结构或功能；
   - `inventive_point_features`：通过完整专利中的背景技术、发明目的、技术方案、效果及附图
     对照后，最能说明发明点的区别性特征；
   - 每个词组的来源位置、为什么属于该角色、预计最可能出现的 `search_scope`。
   只有独立权利要求及其在说明书中的解释可以支撑发明点；从属权利要求可以帮助理解术语，
   但不能把其新增限制并入当前独立权利要求的发明点。
2. `search_scope` 是查询合同的必填字段，只允许：
   - `title_abstract`：客体名称、总括性目的/效果、容易在标题或摘要中直接突出的发明点；
   - `claims`：权利要求常用的构件组合、结构关系和功能性限定；
   - `full_text`：新颖复合术语、具体联接/位置关系、说明书中才可能展开的表达；
   - `classification`：IPC/CPC 等分类号锚点。
   生成器必须记录选择范围的理由；编译器不得把不同范围静默合并成无字段全文查询。
3. 第一轮普通现有技术专利查询只允许形成第 12 条规定的固定五组；事实不足的组跳过并留痕，
   不得用旧多分辨率线、NPL、引证、效果辅助线或 compact fallback 补足数量。五组均使用
   `query_role=inventive_point_precision`，具体字段和检索目的由 `query_variant` 决定。
4. 每条查询统一按以下四类检索信息守门：
   - `feature`：表达式中实际出现、并能映射回独立权利要求真实 feature ID 的技术特征
     关键词；发明点词和类别语境词都属于此类；
   - `subject`：表达式中实际出现的保护客体/类别或其同义词；
   - `classification`：表达式中实际出现、格式合法的 IPC/CPC 分类号。分类号可以来自模块一
     事实，也可以是模型在通读专利后提出并标为 `model_suggested` 的检索建议。
   - `applicant`：只用于 `applicant_plus_object` 的唯一申请人/专利权人字段事实。
   四类中任意两类实际存在即可形成可执行计划；固定第①组以 applicant + subject 满足守门，
   其余四组仍以 feature/subject/classification 中任意两类满足。I2 编译时只出现一类则拒绝。
   一旦固定五线已经由同案、同独立权利要求的成功 I2 run 通过该守门并持久化，I3 以该
   `query_plan_run_id + query_id + provider_expression` 精确回读执行时不得再重复进行旧通用
   单条语义守门：申请人线不得因 adapter 不认识 applicant 锚点而被判为“只有技术主题”，原始
   长特征已原子化进入冻结表达式时也不得要求长句逐字出现。跨案 run、非固定变体、表达式不
   一致或浏览器临时查询仍须拒绝。模型建议分类号
   不得写回模块一事实、日期资格、证据资格或法律结论。
   概念说明可以是完整复合语句，但可执行检索式不要求逐字连续复制整句。一个概念组只要有
   至少一个有意义的部分技术关键词实际出现在表达式中，并由确定性守门映射回该概念绑定的
   真实 feature ID，即视为已经表达该概念；不得只凭模型声明的 `concept_id`/`feature_id`
   放行。每条首轮查询优先保留一至三个已核验的部分技术关键词，避免把完整权利要求机械
   堆成超长 AND。
   特征独立性按 I2 冻结的 feature ID/role 判断。只有与完整客体主题等同的词项才可作为
   重复主题排除；不得提交孤立宽词。
5. 每个用于固定五线的客体、部件、动作或功能概念组必须区分并审计：
   - `specific_terms`：目标专利中的具体原词、近义词和准确跨语言表达；
   - `core_meaning_terms`：模型基于同一冻结概念提炼的核心含义词或合理上位词。
   供应商表达式将两类词放入同一 OR 组，具体词不得被上位词替换。上位词必须保持同一产品
   类别、部件角色、动作或介质路径，例如具体喷水玩具车可以并列核心车辆/喷水玩具类别，具体
   供水管路可以并列供水管/供水，具体吸水结构可以并列吸水结构/吸水；不得扩成脱离目标技术的
   裸 `装置/结构/部件/系统`，不得从候选文献或决定书反推。中文优先保留与锚点词形接近的
   专利写法和核心中文词；英文同时保留无布尔语法歧义的准确短语。固定数量截断应优先保留
   至少一个具体中文词、一个核心中文词以及已有的跨语言对应词，不得把某种语言全部排除。
   发明画像可以保留完整专利措辞用于审计，但可执行检索词必须剥离专利撰写外壳。形如
   `具有/具备/带有/设有/设置有/采用 + 技术含义 + 结构/装置/机构/系统/组件/部件/单元`
   的短语不能因中文不超过 6 字而整体放行，应提炼为仍绑定原 feature ID 的核心动作、功能
   或部件词，例如“具有升降结构”提炼为“升降”。如果该属性短语修饰产品客体，客体组只
   保留后面的产品类别（“具有升降结构的室外消火栓”以“室外消火栓”为客体）；属性短语
   不得进入 `subject_synonyms` 或客体 OR 组。该清洗同时作用于模型画像解析、固定五线编译、
   模块四 GLM 提案守门和离线重编译，禁止用案件词表实现。
6. `synonyms_zh`、`synonyms_en` 和核心含义/上位词字段中的中英混杂项不得进入可执行式；长英文关系句不得压缩
   成 `opposite side` 等孤立位置词；含 `and/or/not` 的短语不得依赖供应商未验证的引号
   语法，应选用模型提供的安全完整表达或语义保持的紧凑表达。
7. 某条固定首轮查询明确返回零命中时，记录成功零结果并继续执行其余固定组；固定五组不创建
   `compact-fallback`，也不自动改写或扩大范围。每组使用独立 module run、幂等键、输入快照
   和响应工件，每个 run 的实际 attempt 上限为 1。全部计划查询均零命中时转人工调整或下一轮，
   不得制造候选或表述为没有现有技术。P002 返回的任何题录继续只属于 `lead`。
8. Portal 与其他执行器必须按 `query_id/query_variant` 逐条执行固定组；一组失败或零命中不能
   静默取消其他组。字段化 `provider_expression` 必须与 I2 冻结表达式一致或通过同一确定性
   规则重建，禁止按旧 role 默认值把新变体降级为旧查询。
9. 英文紧凑化不得把带孔、通道、槽、接口等限定的结构短语退化为孤立的 `unit`、
   `component`、`structure` 等通用构件词；紧凑变体必须保留原特征中的区别性技术词。
10. I2 生成重试与恢复：
   - 第一次模型响应未形成固定五组所需画像事实、且每条满足本节守门的计划时，不得直接把失败
     交给律师；I2 必须把逐条拒绝原因加入下一次生成输入并重新调用模型；
   - 重新生成持续到得到合规计划。为避免相同错误无限空转，连续不合规时，确定性编译器
     可以只使用已经冻结的保护客体、唯一申请人/目标公开号、真实 feature 关键词、功能效果词
     和本轮分类号候选组装缺失的固定组，组装结果仍必须经过同一守门；
   - 每次模型输入、原始响应、标准化结果、拒绝原因和模型信息都分别写入审计工件；后一次
     生成不能覆盖前一次；
   - 输入不足以提供任意两类信息、模型/服务不可用或用户取消时可以明确失败；普通的单次
     JSON 格式、角色遗漏或组合不合规不属于律师需要处理的终止原因。
   - live I2 的持久化 job 对 GLM 传输失败只尝试一次；同一网络超时不得由 worker 再放大为
     三个长调用。只有模型已返回内容但确定性校验不合格时，I2 才可在同一 job 内携带具体
     校验原因重新生成一次，随后用目标专利已确认事实作一次确定性补齐或明确失败。
11. I2 在生成查询前必须只根据目标专利建立 `mechanism_model`：
    - `component_roles`：部件及其在整体装置中的角色；
    - `topology_relations`：连接、包含、穿过、支撑和相邻关系；
    - `motion_state_relations`：运动方向、位置、状态和动作顺序；
    - `control_relations`：触发、锁定、释放、选择性联接和控制关系；
    - `technical_roles`：上述结构在整体工作过程中的技术作用。
    每项都必须绑定目标专利原文位置和 limitation/feature ID。模型同时为目标中的同一角色
    生成 `original_terms`、`role_equivalent_terms` 和 `operation_terms`；同功能但不同结构
    关系或不同机构动作的表达不得放入 role-equivalent。联接/接合、锁定、解锁、脱开/分离
    必须作为不同动作族处理；目标只记载选择性联接时，不得扩展为锁定机构、解锁机构或
    锁定/解锁动作。每条可执行检索式的主 feature anchor 必须来自 `original_terms`、独立
    权利要求原词或可回溯的发明点短语；通过来源校验的 role/operation equivalent 只能与
    该原始锚点放在同一 OR 组中，不得替代原始锚点成为单独查询。历史缓存画像即使已含
    `mechanism_model`，重编译前也必须按当前规则清理不受目标原文支持的扩展词。
    可执行 feature anchor 还必须是一个可独立检索的原子技术概念。模型返回的说明句、
    关系描述或用顿号、逗号、分号并列的多个概念必须先拆分，不能作为一个关键词或同一个
    OR 组写入供应商表达式。例如“中间位置、选择性联接”应拆为“中间位置”和
    “选择性联接”；短召回线优先只使用信息量更高的“选择性联接”，确需位置限定时另建
    AND 组加入“中间位置”。“位置选择性联接装置”这类本身表达单一技术概念且没有并列
    语义的术语仍可整体保留。
    历史同源画像没有 `mechanism_model` 时，只允许根据目标权利要求中已经冻结的结构/动作
    措辞恢复通用动作族，并在输出中标明兼容恢复；不得读取候选文献或测试答案。每项查询用
    `feature_term_groups` 保存同一 feature 的目标原词、角色等价词和动作词，P002 编译器
    不得因固定截断丢掉关键作用词。
12. 首轮普通现有技术专利查询固定为以下五个 `query_variant`，每种至多一条：
    - `applicant_plus_object`：`AN:(唯一申请人/专利权人)` AND 客体及同义词的
      `TTL OR ABST`。真实 P002 只执行该正向表达式；供应商原始前 10 先完整冻结，再由本地
      确定性层按规范化公开号主体排除目标专利（包括 A/B/U/S 文献种类变体）并记录排除项。
      申请人缺失或歧义时跳过；公开号缺失时保留检索线，但必须留痕且不得声称已排除；
    - `title_object_plus_desc_inventive`：客体及同义词放 `TTL`，首个核心发明点及同义词放 `DESC`；
    - `classification_plus_desc_inventive`：至多两个客体相关 IPC/CPC 放分类字段，首个核心发明点
      及同义词放 `DESC`；
    - `desc_object_plus_desc_inventive_plus_effect`：客体、首个核心发明点、技术效果三组均放 `DESC`；
    - `title_keyword_object_plus_desc_function`：客体及同义词放 `TTL OR ABST`（供应商无独立
      keyword 字段时的确定映射），核心发明点功能描述及同义词放 `DESC`。
    旧的 `maximal_similarity_precision`、`object_plus_inventive_point`、
    `subject_classification_plus_inventive_point`、`object_plus_inventive_classification`、
    `object_plus_two_inventive_points`、`system_architecture_recall`、`title_abstract_concept`、
    首轮 NPL/引证/效果辅助线不再首轮发射；它们只可保留为历史契约或后续 gap 明确需要的兼容
    类型。五组只绑定画像顺序首个核心发明点，不因多个发明点复制同型线；每个 OR 组最多 5 个
    成员。编译器必须把该概念的具体词与核心含义/合理上位词同组 OR，避免把“车主体底”“吸水
    口”“第一供水管”“水泵进水口”等全部拆成独立的狭窄 AND 组；同一发明点优先编译为少量
    语义组，每组内部用具体词+核心词扩大召回。截断时按第 5 条保留具体中文词、核心中文词与
    跨语言对应词，中文继续执行 ≤6 字原子化。
13. 测试决定书、已知对比文件及其公开号、题名、摘要或专用词不得出现在生产 I2 输入、
    prompt、编译器和运行时配置中。测试基准只能在查询和搜索结果全部冻结后，由独立评估器

    排名问题。

    `subject/inventive_point/general` 语义角色。只有模型或模块一事实能够支持时才可区分

15. live I2 可以复用同一 Investigation、同一独立权利要求、同一不可变源文件的最新成功

      拆成独立 AND 关键词（如 无线 AND 耳机），不得留在客体词内部。英文客体仍保留完整
      短语（water gun 不得裁成 water），6 字上限只约束中文原子词。
    - 权利要求整句（所述……具有/设置有/电性连接/对应……设置……）禁止作为检索词；
      确定性层必须从中提炼原子技术名词并按 AND 组合（如「所述耳机本体内具有PCBA板，
      所述PCBA板电性连接有喇叭和电池 AND 所述耳机本体对应所述喇叭设置有出音孔」提炼为
      PCBA板 AND 喇叭 AND 电池 AND 出音孔）。
    - 提炼必须保守：只删除「所述/具有/设置有/电性连接/对应/本体内」等通用连接措辞和
      重复指代，保留区别性技术名词；提炼后无法得到任何原子技术名词的特征按「未形成」
      告警处理，不得原句放行。
    - 该规则适用于 I2 全部检索线（含模型生成、确定性组装、守门规范化与离线重编译），
      对任意目标专利通用，不得按案件编写特例词表。


### 4.2.3 I3-F 取文前候选清理

每条实际检索仍按供应商原始顺序冻结前 10 篇。I3-F 位于所有 I3-P/I3-NPL 搜索完成之后、
任何 I3-E 全文请求之前；它不能改变原始检索结果，只生成一个可重放的取文计划。

I3-F 的输入必须来自同一 Investigation、同一独立权利要求已经持久化的搜索 module run，
并读取同案最新成功 I2 的 `invention_search_profile`、`mechanism_model` 和 limitations。
live 模式不得让浏览器提交或改写候选题录、模型判断、文献 stage、哈希或资格。

清理分两层执行：

1. **确定性身份合并**：
   - 同一 provider 稳定文献标识只保留一次；
   - 同一申请号的多个公开文本合并为一个候选组；
   - 同一规范化公开号去掉 kind code 后相同的 A1/A2/A3/A4、B1/B2 等版本合并；
   - provider 明确返回可靠 family id 且题名/身份没有冲突时可以合并为同族组；
   - 代表文本优先选择具有完整取文标识、实质公开文本 kind code 和更早原始排名的成员。
   被合并成员继续保存原查询、原排名、公开号、申请号、组键和代表文献；代表取文失败时，
   其他成员只能作为同一组的受控取文替代线索，不能重新计为另一份对比文件。
2. **保守的技术相关性复核**：
   - 程序先用保护客体、发明点/机构词、分类锚点和候选题名/摘要/分类号保护明确正向命中；
   - 剩余唯一代表可以由一次批量 GLM-4.6V 调用判断
     `keep_relevant`、`keep_uncertain` 或 `exclude_obvious_unrelated`；
   - 只有候选元数据已经明确属于不相容技术领域，且没有显示目标机构、部件角色、连接/
     运动/控制关系或可能的跨领域技术启示时，才允许
     `exclude_obvious_unrelated`；
   - 无摘要、无分类、题名过泛、术语跨语言、机构关系可能相通或模型理由不完整时，必须
     `keep_uncertain`；
   - GLM 超时、不可用、JSON 不合规或漏判某候选时，该候选失败开放为
     `keep_uncertain`。模型不得决定日期资格、披露、D1 或专利有效性。

I3-F 输出至少包含：

- `raw_candidates`：全部原始前十命中及查询/排名谱系；
- `candidate_groups`：组键、代表、成员和代表选择理由；
- `duplicate_candidates`：被合并版本及其代表；
- `excluded_candidates`：明显无关候选、理由、使用的元数据和规则/模型版本；
- `fetch_candidates`：实际进入 I3-E 的唯一代表；
- 原始数、唯一组数、排除数、重复数、取文数和预计减少的全文请求数；
- 模型 prompt hash、原始响应工件、规范化决定、失败开放警告和审计哈希。

I3-F 不得使用决定书答案、公开号白名单或具体案件硬编码词表；不得因某候选没有命中目标
字面词就自动排除。清理后的所有 `fetch_candidates` 必须取文，不能再按 2 篇、5 篇或得分
做第二次隐藏截断。

### 4.3 非专利材料

- 关键日前已公开且来源链合格的非专利材料可以进入新颖性与创造性分析。
- 关键日后首次公开的非专利材料只能作为术语、引证或更早来源追溯线索。
- 非专利材料不得标记为抵触申请。
- 非专利检索源不执行专利 IPC/CPC 字段。NPL 可执行表达式必须在实际文本中同时包含保护
  客体/类别和至少一个真实技术、机构或作用特征；专利分类号不能替代论文关键词，也不能把
  `object_plus_inventive_classification` 中只剩客体宽词的表达式复制为 NPL 查询。
- I2 补齐 NPL 分线时，只能复用实际文本已经包含 `subject + feature` 的同案查询，并移除
  分类字段；Portal 和 I0 必须把 `text + subject_terms + feature_terms` 一并传给 NPL
  adapter，不得只传表达式后丢失锚点语义。
- 复合 NPL provider 在分发到 arXiv、OpenAlex、Crossref 和公共 Web 之前只做一次共同
  查询校验。共同输入无效时返回一项明确的检索式错误，不得伪装成四个 provider 分别故障；
  共同输入有效后，各来源的真实网络、响应结构或零命中结果仍分别审计。

### 4.4 资格结果

每个 `claim_investigation_id + document_version_id` 必须单独保存：

- `novelty_eligible`
- `inventive_step_eligible`
- `lead_only`
- `needs_human_review`
- `excluded`
- 日期事实、适用通道、规则版本和原因代码

结果页和导出不得把不同权利要求的资格聚合为一个全局布尔值。

## 5. 每轮执行算法

每项独立权利要求都由 `I0` 独立维护一个已持久化的检索前沿，而不是把整个目标专利作为一次不可分割的搜索任务。单轮不是“一篇对比文件”，D1/D2/D3 也不与第 1/2/3 轮机械对应；一轮可以取得多篇材料，而一篇材料也可以被多个独立权利要求分别比对。

```text
已确认关键日 + 完整继承限制
  -> 创建本轮双线查询计划
  -> 冻结供应商原始前十候选
  -> I3-F 合并重复版本并排除证据充分的明显跨领域候选
  -> 对剩余唯一代表取得并冻结真实文献版本
  -> 逐独立权利要求执行日期资格
  -> 每篇文献分别执行 I4-S 全限制比对
     -> 任一单篇合格文献完整覆盖：输出新颖性 CC，停止该权利要求默认检索
     -> 没有单篇完整覆盖：选择或重选正式 D1，冻结区别特征及其作用/效果
        -> I4-O 显而易见性预分析 D1 启示、惯用手段、动机、反向教导和效果
           -> 已满足跳过条件：停止普通结构检索，进入组合分析
           -> 惯用手段待补证：只生成公知常识证据查询
           -> 组合理由待补证：只生成组合启示/动机查询
           -> D1 无启示且非惯用手段：只生成直接特征查询
              -> 搜索、候选清理、取文、日期资格、逐篇 I4-S
              -> 必要时重选 D1 并重新运行 I4-O；必要时进入下一 gap 轮
           -> 第五个 gap 轮仍未全部覆盖：标记 exhausted，继续组合分析和大 Claim Chart
```

### 5.1 第一轮

`I2` 第一轮生成：

- `invention_search_profile`：保护客体/类别、类别共有技术语境、发明点区别特征及其来源；
- 第 4.2.2(12) 条固定五组中事实齐备的普通现有技术专利线，每组至多一条、总数不超过五条；
- 中文及主要外文同义表达；
- IPC/CPC 查询；
- 唯一申请人/专利权人 + 客体检索线；供应商原始前 10 冻结后在本地按规范化公开号排除
  目标专利，并保存排除记录；
- 普通现有技术和抵触申请候选两个专利日期通道；
- 专利与已批准非专利 provider 的明确范围。

每条查询必须保存 `query_role`、`query_variant`、`search_scope`、客体/分类锚点、分类
语义角色、特征角色、来源、范围选择理由、`allow_zero_results` 和
`compact_fallback_allowed`；固定第①组以 applicant+subject 满足守门，其余组按
feature/subject/classification 三类任二。查询不得由只含一类信息的孤立宽词组成。类别共有
特征用于召回和语境约束，不能仅因其被文献公开就生成新颖性结论。

上述锚点合同在 I2 生成/编译阶段完成。I3 执行固定五线时必须从同案成功 I2 run 回读并核对
`query_plan_run_id`、`query_id`、固定 `query_variant` 和冻结 `provider_expression`，核对通过后
原样发网，不得把该查询再次降格为无谱系的通用字符串并套用旧单条守门。该放行不适用于 NPL、
gap 查询、manual 输入或任何未能精确匹配冻结计划的查询。

同一 role 下的五个固定 variant 必须各自创建 P002 run、幂等键、输入快照和响应工件。任一
固定线返回零命中时记录为成功零结果并继续其他变体，不创建 compact fallback。申请人线
不得向 P002 发送其不接受的 `NOT PN`；目标排除发生在原始响应工件和原始排名冻结之后、
候选汇总之前。全部执行线结束后，以各线供应商原始前 10 经该确定性排除后组成去重待取文集合。

### 5.2 D1 后的显而易见性预分析与补证检索线

首轮完成且没有单篇完整覆盖后，`I4-C` 先选择 D1，并以目标独立权利要求版本、D1 文献版本和
当前 I4-S 规则版本冻结区别特征。每个区别特征至少保存：

- 目标限制原文与 feature ID；
- D1 未披露/不确定的具体边界；
- 目标中的构件角色、连接/位置/运动/状态/控制关系；
- 由目标专利原文支持的技术作用或技术效果及证据锚点；
- 对应 D1 disclosure、document version 和 I4-S run。

生成新查询前必须运行独立的 `I4_O_OBVIOUSNESS_PRECHECK`。它读取当前 D1 版本、区别特征、
D1 全文及 I4-S 证据、目标专利作用/效果和当前全部日期合格语料；输出不得把“D1 未直接公开”
等同于“必须继续检索”。每项区别特征或特征组至少保存：

- `feature_group_id`、`feature_ids` 和分组理由；
- `objective_technical_problem`；
- `d1_teaching_status = supported | not_supported | uncertain`、D1 原文、位置和从该启示到区别
  特征的映射链；
- `d1_teaching_path_complete`：区分“D1 只给出改进方向”与“D1 已独立给出足以到达该差异的完整
  改造路径”；仅前者不得绕过仍待补证的惯用实现手段；
- `routine_means_status = supported_by_citable_evidence | preliminary_candidate | not_supported | uncertain`，
  以及公知常识证据或律师确认引用；
- `modification_motivation_status = supported | not_supported | uncertain` 和具体改造路径；
- `teaching_away_status = present | absent | uncertain`；
- `effect_predictability = predictable | unexpected | uncertain`；
- `search_route = skip_structural_gap_search | search_common_knowledge_evidence |
  search_combination_evidence | search_direct_feature_evidence | human_review`；
- 证据充分性、律师确认状态、输入版本键和可读理由。

`skip_structural_gap_search` 必须由确定性守门要求以下条件满足：D1 有具体启示或该差异属于惯用
替换/公知常识这两条路径至少一条成立，并且存在改造动机与可执行修改路径、没有反向教导、
技术效果可预期。该分流只免除寻找
完全相同结构的冗余检索；若惯用手段只有模型预判、没有可引用证据或持久化律师确认，则最终
证据不得标为完整，并将唯一补证目标设为 `search_common_knowledge_evidence`。反向教导存在、
效果不可预期或事实冲突时必须转 `human_review`，不得自动输出缺乏创造性的确定结论。

`I4-O` 还必须遍历当前调查中所有非 D1、日期合格、`analysis_ready=true` 且 I4-S 已成功的
文献，保存直接特征覆盖和组合启示线索。现有语料直接同角色/同作用覆盖区别特征时可以关闭
`search_direct_feature_evidence`；仅功能目的相近、结构关系不同的文献不得关闭直接特征缺口。

`I2-G` 只消费最新 I4-O 的未解决搜索目标：直接特征、公知常识或组合启示。每条查询必须绑定
一个或多个目标 feature/group 和 `target_gap_type`，不得重算一套独立的二元覆盖结论，也不得
为已有可引用证据完整关闭的特征继续生成完全相同结构查询。本轮每一个尚未由可引用证据关闭的
区别特征都必须至少生成并执行一条以该 feature 为主目标的查询；公知常识、NPL、抵触申请、
组合启示等附加通道不能占用或替代这项逐特征最低覆盖。`human_review`、模型预判惯用手段、
版本键不完整或仅有功能近似都不构成零查询理由：这些状态可以改变查询的补证目标并继续保留
律师复核标记，但只要特征尚未由可引用证据关闭，就仍须有主查询。本轮新取得的每篇文献仍执行
完整 I4-S，因此任何一篇意外完整覆盖全权利要求时仍立即触发新颖性停止。

普通专利主检索线进一步固定为“一项未解决区别特征一组”，不得把两个区别特征合并成一组，
也不得为同一区别特征生成两条普通专利主线。每组只允许两个布尔概念组：

1. 客体组：从与目标客体结构机理相近的邻近类别、上位类别或可检索下位类别中选词，但排除与
   目标专利保护客体完全相同的中英文类别名称；组内同时包含中文、英文及可追溯的上下位概念/
   同义词，并以 `OR` 连接；
2. 特征组：使用该区别特征的特征点词，同时包含中文、英文及可追溯的上下位概念/同义词，并以
   `OR` 连接；不得掺入其他区别特征；
3. 两组之间只用一个 `AND` 连接，表达式固定为
   `（邻近客体中文 OR adjacent object English OR 上下位/同义词） AND`
   `（特征中文 OR feature English OR 上下位/同义词）`。

例如目标客体为水枪，未解决特征分别为吸水口和加压储水区域时，本轮普通专利主线必须恰好两组，
可分别形成为`（枪 OR gun） AND（吸水 OR 进水 OR 入水 OR water intake）`及
`（枪 OR gun） AND（加压 OR 存水 OR 储水 OR pressurized storage）`。该示例只说明通用结构，
运行时词项必须来自目标画像、区别特征和本轮模型对上下位/同义概念的可审计分析，不得写死案例词表。

完全相同客体守门只把目标实际保护客体及其语义等同类别名视为 exact，不得把画像中的上位设备、
设施、器材、装置等宽类别仅因位于 synonym 列表就判为 exact。模型一次返回的客体组如果混有 exact
词和合格上位/邻近词，确定性层先移除 exact 词并把移除项写入调用审计和计划 warning；剩余客体组仍
满足中文、英文各至少一项时继续编译。过滤后缺失任一语言时 fail closed，不得重新放回 exact 词补数。

`I2-G` 是后续轮的唯一查询生成模块：首次进入 gap 阶段时，它必须一次性形成一个版本化
`gap_query_matrix`，在同一组合中输出第 1—5 轮各自的 I4-O run/version、语义策略、允许检索的
feature/group IDs 以及实际查询计划；I0 不得再另建 `I2_QUERY_PLAN` 生成 gap 查询，也不得在
前一轮执行结束后临时调用模型重写下一轮。同一矩阵内每一轮可以使用独立 I2-G child run 形成和
校验，但五个 child run 必须由同一个 `matrix_id + matrix_version + matrix_binding_sha256` 绑定，
并在首次 provider 执行前全部进入终态；某轮计划最终失败时，该矩阵行冻结为 failed/skipped 并
保存错误，不得阻断其他矩阵行和后续 provider 执行。若 I4-O 没有未解决搜索目标，I2-G 输出 `queries=[]`、
`generation_source=obviousness_precheck_resolved` 的可审计零查询计划；I0 跳过 provider，但仍
运行 I4-I 并更新大 Claim Chart。若仅剩律师确认，不得伪装为检索完成。

gap provider 与本轮全部 I4-S 收口后，I0 必须在同一 iteration 立即用当前 D1、最新区别特征
和严格版本键重新运行 I4-O。若 D1 重选、语料或资格变化，旧预分析必须失效；若本轮已经解决
全部搜索目标，应在本轮完成 I4-I 与大 Claim Chart 后停止后续 gap 检索，不得多建下一轮零查询。
若仍有一个或多个区别特征没有可引用披露证据，I0 只能执行已冻结矩阵中的下一 gap iteration，
直至全部关闭或完成第五轮；律师模块九在当轮收口后自动排入下一冻结轮次，不再要求用户为错误轮
逐次放行。已经关闭的 feature 在后续轮中标记 `skipped_feature_resolved`，不发
provider；不得因为其他 feature 已关闭而整体停掉尚未解决 feature 的查询。

五个 gap 轮不再共享同一词池后仅靠换序或轮换成员制造差异。矩阵生成阶段必须一次完成五轮的
跨轮集合对账；每个仍未关闭的 feature 必须预先冻结五轮查询，并严格使用各轮唯一对应的语义策略：

| `gap_search_iteration` | 客体组视角 | 特征组视角 | `gap_search_strategy` |
| --- | --- | --- | --- |
| 1 | 与目标客体结构机理接近的相邻产品类别 | 目标区别特征的直接结构名称及近义表达 | `adjacent_object_direct_structure` |
| 2 | 优先采用仍有区分度的上位产品/设备类别；目标本身已过宽、继续上位只会得到泛词或无法形成合格双语组时，采用与区别特征用途/角色相符的合适下位产品类别 | 同一结构族的上位、下位及结构同义词 | `broader_object_structural_family` |
| 3 | 解决相同技术问题或实现相同功能的产品类别 | 动作、功能和技术角色表达 | `same_function_object_action_role` |
| 4 | 区别特征所在的子系统或部件类别 | 构件关系、运动/控制关系或介质/能量路径 | `subsystem_component_relation_path` |
| 5 | 采用相同工作原理的类比领域客体 | 工作原理、技术效果和等效机制 | `analogous_domain_principle_effect` |

每轮仍维持“一个双语客体 OR 组 AND 一个双语特征 OR 组”，只是两个概念组必须从本轮对应词族
形成。模型只可在本轮语义视角内补充候选词；确定性编译器不得因本轮词族不足而回退上一轮词池、
重排旧词、仅增删标点或删除限定后形成裸“装置/结构/部件/系统”。第 5 轮需要类比领域客体时，
该客体必须由冻结画像或本轮模型对工作原理的通用化分析支持，代码不得凭案件词表猜造。无法形成
当前轮合规双语概念组时应明确失败，或仅启动补齐当前轮词汇的受控任务，不得复发旧查询或提前
宣称检索完成。实际执行产生的零命中、取文失败或 I4-S 未覆盖事实只更新矩阵行的执行状态和失败
谱系，不得在同一矩阵版本内改写后续轮的冻结查询；D1、区别特征、limitation/date/I4-O/I2-G
版本绑定变化时，旧矩阵的未执行行失效，历史保留并生成新的 matrix version。

第 2 轮的上下位选择必须在模型响应审计和计划 warning 中保存理由：说明为何现有客体还能有效
上位，或为何继续上位只会得到泛化设备词，以及所选下位产品如何承担目标区别特征的相同用途和
技术角色。不得仅因“无可用上位概念”把第 2 轮判为失败。

后续查询必须记录：

- `search_objective`
- `target_gap_type`
- `gap_feature_ids`
- `anchor_document_version_id`
- `parent_iteration_id`
- `gap_search_iteration`（首轮为 0，区别特征检索为 1–5）
- `gap_query_matrix_id` / `gap_query_matrix_version` / `gap_query_matrix_binding_sha256`
- `gap_query_matrix_status`（`planned` / `running` / `completed` / `superseded` / `exhausted`）
- `gap_search_strategy` / `gap_search_strategy_label` /
  `gap_search_strategy_description`（由轮次确定并冻结到计划及每条查询）
- `covered_difference_feature_ids` / `uncovered_difference_feature_ids`
- `obviousness_precheck_run_id` / `obviousness_precheck_version`
- `search_route` / `feature_group_ids`
- `existing_corpus_reuse`（文献版本、内容哈希、I4-S run/rule、作用相同依据）
- `previous_iteration_failure_reason`
- 查询语言、provider、日期通道和实际执行状态

跨轮重复文献不得因复用而丢失本轮发现血缘。每次命中仍保存本轮 `query_id`、provider rank、
iteration 和 candidate lineage；只有 document version/content SHA、目标 limitation version/SHA、
date qualification revision、I4-S prompt/rule 和完整 input binding 均一致时，才能复用先前的 I4-S
输出并记录 `reused_from_i4s_run_id`，同时跳过重复取文和模型调用。任一键变化都必须重取或重跑。
I4-S 的复用不等于创造性结论复用：D1 选择或组合语料集合变化时，I4-O 与 I4-I 必须以新输入重跑。

I4-O 复用只有在 D1 版本、全部输入文献版本/内容哈希、目标 limitation version、日期资格
revision、I4-S run/rule、prompt/rule version 完全一致时才有效；任一项变化必须重新运行。

### 5.3 文献处理顺序

每个原始候选严格依次经过：

1. lead 记录；
2. I3-F 取文前候选清理：按同申请/同公开号版本/可靠同族合并，并只排除有充分题录证据的
   明显跨领域候选；不确定候选继续保留；
3. 对每个保留组的唯一代表，专利 lead 先按智慧芽公开号/申请号映射到 EPO OPS 同一
   publication reference；EPO
   明确无覆盖/无媒体时再以同一 `patent_id + pn` 调用智慧芽 P020。两条路径都必须执行真实
   文件/页面获取、MIME/大小/身份校验；非专利材料按其来源 adapter 取文；
4. 原始响应或合规快照、SHA-256 和来源链保存；
5. 日期资格；
6. 生成 `ReadablePatentDocumentV1`：EPO description/claims XML 优先，其次使用 PDF
   文本层，最后仅对无文本页面进行 OCR；保存逐段/逐权利要求/逐页锚点、JSON/Markdown
   工件、覆盖统计、标准化版本和 `analysis_ready`；
7. `I4-S` 单文献全限制比对；
8. 新颖性停止判断；
9. 未触发停止时才进入 D1 候选或创造性组合。

模块五在第 3 步发起 EPO/P020 取文前，必须先按“带 A/B/U/S 等文献种类号的
完整公开号”查询同一环境的历史全文缓存。缓存只在以下条件全部成立时命中：

- 公开号及 kind code 完全相同，不得按标题、主号、同族、特征序号或文字相似度模糊命中；
- 原始工件位于当前测试/正式环境自己的工件根目录内，现场重算的字节数和 SHA-256
  与冻结记录完全一致；
- 可读化结果的源文件 SHA、标准化版本、JSON 工件哈希、全页处理状态和
  `analysis_ready` 都通过校验。

完全命中时，模块五直接复用原文与已校验的可读化/OCR 结果，不再请求 EPO/P020，
也不重复 OCR。若原文哈希有效但可读化版本已过期，只能从该冻结原文在本地重建
当前可读化结果，仍不得重复网络取文。号码不同、kind code 不同、哈希/大小不符、
工件损坏或可读性无法验证时，必须回到正常 provider 链。

全文复用只是取文和可读化层复用：必须保留本次 query/candidate/I3-F lineage，并对当前
案件重新执行日期资格核验。模块六 I4-S 必须绑定当前目标专利、当前独立权利要求、
当前 limitation 集合和当前规则重新比对；历史日期结论、特征序号或 I4-S 披露结论
不得随全文缓存一并复用。

搜索摘要、题录片段、模型记忆或未取得的 PDF URL 不得跳过步骤 2–5。

`ReadablePatentDocumentV1` 至少包含：

- `normalization_version`、原始内容 SHA-256、文献标识与来源；
- `text_source = epo_xml | pdf_text | ocr | mixed`；
- `pages[]` 的页码、文本、文本来源、字符数和原始工件锚点；
- `sections[]` 的说明书段落/权利要求编号与文本锚点；
- `coverage` 的总页数、文本页数、OCR 页数、缺失页数；
- `analysis_ready`、`analysis_readiness_reason`；
- JSON 与 Markdown 工件 ID/SHA-256。

原始文献取得和可读化是两个状态。普通文本提取可以在 I3-E 当前作业内完成；扫描页 OCR 使用
现有持久化作业机制后台运行，默认最多 2 份文献并发、单份 120 秒。缓存键固定为
`content_sha256 + normalization_version + OCR language/config`。OCR 超时或失败保留
`retrieved_document`，但 `analysis_ready=false`，不得交给 I4-S 冒充全文分析。

每条实际执行的专利查询按供应商原始排序冻结前 10 篇候选，并把全部原始候选提交 I3-F；
不得在律师模块编排、Portal 或 I3-F 入口另行使用 2 篇、5 篇等更小隐藏抽样。I3-F 合并
同一申请、同一公开号的不同公开版本和可靠同族，并排除题录证据充分的明显跨领域文献后，
所有唯一代表必须提交取文。同一文献只需取文和 I4-S 一次，但必须保留它来自哪些查询的
lineage。每篇成功取得真实全文的保留文献都必须分别执行 I4-S。被排除、被合并、取文失败、
只有 lead、日期资格不满足或 I4-S 最终失败的文献仍逐篇留在结果中并显示原因；只要仍有
已取得全文的保留文献未完成 I4-S，律师模块五不得显示为全部完成。

搜索排序阶段可以记录 `candidate_d1_score`，但在步骤 2–6 完成前不得创建正式 D1 版本。完成本轮所有可用候选的单文献矩阵后，系统先执行单篇完整覆盖检查；只有没有任何合格单篇完整披露时，`I4-C` 才能从候选集中正式选择 D1。

后续轮次中的 D2/D3 不是按命中时间编号。它们应按对当前区别特征的有效增量选择，并保存
选择前后的累计覆盖边界。累计覆盖边界只供创造性组合使用，不能回写成任何单文献的新颖性覆盖。
第五个 gap 轮收口后，报告默认选择 D1 加最多 5 篇普通现有技术文献形成大 Claim Chart；
非 D1 文献先按新增确认披露的区别特征数量降序，再按确认披露的必需特征总数、证据完整度、
日期确定性和稳定 document ID 排序。少于 5 篇时如实展示，不补造。

### 5.4 轮次提交与检索前沿

每轮结束必须原子提交一个不可变的 `claim_round_frontier`（名称可在实现中映射，但语义不得缺失），至少冻结：

- 本轮参与比对的文献版本集合及每篇的日期资格；
- 每篇文献自己的单文献覆盖矩阵；
- 是否存在单篇完整覆盖及其文献版本；
- 当前 D1 版本、候选集、选择因素和替换理由；
- 当前用于创造性分析的增量文献集合及累计覆盖边界；
- 四类 open/closed gap、gap 指纹和与上一轮相比的实际增量；
- 下一轮的检索目标、预算和停止/继续理由。

`I0` 只能从已经提交的前沿创建下一轮。查询数量、搜索命中数量或文本相似度上升不自动等于取得进展；
只有新增日期合格文献并关闭至少一个区别特征、单篇覆盖增强到新颖性停止、或为既有区别特征补齐
可核查的同作用证据，才算 gap 轮取得实质进展。无进展轮仍计入 1–5 的 gap 轮次并保存失败原因，
但不得因为一轮无进展就提前宣称已穷尽全部检索路径。任一轮的 I2-G、provider、候选清理、取文、
日期资格或 I4-S 发生错误时，本轮以 partial/failed 事实原子收口；错误轮不得阻断其后的冻结轮，
自动流程必须继续，直至五轮均已执行、按已关闭特征跳过或用户取消。

## 6. 单文献新颖性检查

`I4-S` 的基本单元为“一项权利要求 × 一份文献版本”。输出至少包含：

- 每个特征的 `disclosed`、`not_disclosed`、`uncertain`；
- 对应的权利要求技术特征原文，不得只返回内部 feature ID；
- 原文、译文、页码/段落/权利要求/附图位置；
- 文本和图像实际使用数量；
- 直接明确披露理由和不确定原因；
- 模型、提示词、规则和输入工件版本。
- 目标权利要求与对比文件各自的整体机构/工作过程摘要；
- 每个特征的目标部件角色、对比文件对应结构、连接/运动/状态映射依据和多条证据锚点。

只有同一份日期合格文献对完整权利要求的全部限制均为可核查的 `disclosed`，才触发 `novelty_evidence_complete`。不同文献的披露不得在新颖性 CC 中合并。

披露状态必须与理由一致：

- 已取得并完整审阅文献全文/必要附图，且审阅结果明确为没有公开该技术特征时，使用
  `not_disclosed`；否定性判断可以用“全文未检出对应披露”的审阅范围作为位置，不要求伪造
  不存在的正向引文；
- 文献内容或附图不完整、术语对应关系不清、位置无法核验、证据相互冲突时使用
  `uncertain`；
- 模型调用、解析或结构化输出失败时使用 `analysis_failed`；
- 模型理由明确写明“未披露/没有公开/未记载”而状态为 `uncertain` 时，确定性一致性层应在
  排除“不确定是否未披露”等保留语境后改为 `not_disclosed`；不得向律师显示互相矛盾的
  “理由未披露、判断暂不能确认”。

结构披露判断必须遵守：

- 术语相同不自动等于结构相同；术语不同也不自动否定披露；
- 不要求目标特征与对比文件在构件名称、零件数量、拆分方式或具体外形上逐项相同。对比文件
  的一个构件或一组相连构件，只要在整体方案中承担实质相同的部件角色，并实现对应的介质/
  能量路径、连接拓扑、运动/状态变化和控制关系，即可确认 `structural_equivalent` 披露；
- 一个集成结构可以同时映射目标权利要求中多个分别命名的特征。不得仅因对比文件没有把
  阀体流道、移动杆件、连接管路等分别使用目标术语命名，就逐项否定其结构角色；
- 首轮已经形成多项正向结构映射、但同一整体机构中的其他特征仍为未披露、不确定或分析
  失败时，I4-S 应只对其中最多八项最有结构对应可能的开放特征执行一次有界结构复核。复核必须沿完整介质路径、连接
  拓扑和动作链检查集成构件，不得重答首轮已通过特征；复核传输失败时保留首轮已守门结果，
  记录 `structural_review_status=model_error` 和安全错误码，不得把该篇作为已完成实体判断
  进入新颖性、D1 或组合聚合，也不得无限等待；模块五批次只自动补跑一次，仍失败则明确
  partial 收口；
- 从文献整体工作过程能够直接、无歧义且必然推出目标角色或关系时，可以标记
  `necessarily_implicit`。输出必须提供闭合的必要性链：已明确公开的构件/关系、运行所需的
  物理或机械条件、由此必然存在的目标角色/关系，以及为何与全文相容的合理替代路径已经
  被排除；
- 通用名词不得脱离工作过程无条件等同。例如 `reservoir` 只有在全文机构表明其参与受压
  储液和排液时才可映射为压力罐；`check valve` 只有在全文显示活塞/杆件于阀体流道中运动并
  控制通断时，才可把该集成结构映射为可移动阀杆和阀导管；
- 只有功能、目的或效果相同，但结构角色、工作路径、连接/运动关系或必然性仍未确定时，
  不得标记为披露；
- `analysis_ready=false`、覆盖不完整或缺少必要附图时，禁止输出 `not_disclosed`，必须为
  `uncertain` 或 `analysis_failed`。

实质相同标准（2026-08-06 用户最终解释）：比对必须基于对比文件全文理解其整体机构后判断；
特征名称不同不构成否定。「实质相同」指结构和位置关系与目标专利没有不同、且功能作用相同；
对比文件中的下位概念或具体构件只要承担了目标特征的相同角色（如钉子承担固定单元的作用），
即视为公开，不要求名称、构件划分或具体结构完全相同。该解释不放宽必然隐含披露的
物理/机械必要性链要求。

候选构件发现（2026-08-06 用户决定，实质相同标准的执行方式）：逐特征判断之前，模型先基于
对比文件全文，为每个目标特征的角色列出对比文件中可能承担该角色的候选构件/结构区域清单
（含原文引文与位置、承担该角色的理由，允许显式「无候选」）；逐特征比对带着这份共享候选
清单做功能核对。候选清单注入首轮各批次、整体结构复核与守门复核的 prompt，全部批次看到
同一份清单；清单中每条引文必须经确定性层回验真实存在于对比文件全文，无法回验的条目
丢弃并留痕；发现步骤调用失败不阻断既有比对流程，降级为无清单运行并记录审计字段；候选
清单与回验结果持久化到 run 输出。

确定性守门（2026-08-06 起，触发、对账、降级与留痕由程序执行，模型只做语义判断）：

- **否定断言核验**：特征结论为 `not_disclosed`（或理由为「未提及/未发现/无对应」的否定
  断言）时，确定性层围绕「承担该特征角色的候选构件/结构区域」核验——特征核心词、绑定
  同义词及候选角色词在对比文件全文中存在而未在推理或结构证据中被逐一处理的，不得直接
  输出 `not_disclosed`；触发一次有界候选复核，由模型逐条说明每个候选为何不对应；复核后
  仍有未处理候选的降级为 `uncertain` 并留痕；
- **跨特征一致性对账**：全部批次与结构复核完成后，确定性层检查——父特征已经角色映射判
  披露的，其子特征不得以「无该结构/未提及」为由判 `not_disclosed`；反向同样成立——子特征
  （组成结构）已判披露的，共享其核心构件的父特征不得反向以「无该结构」为由判
  `not_disclosed`；`reference_mechanism_summary`
  或其他特征证据/映射中出现的构件，不得在另一特征层被判「全文未提及」。检出矛盾时把矛盾
  双方连同双方推理放进同一上下文做一次有界合并重判；重判后仍矛盾的降级为 `uncertain`
  并写入告警。
- **复核留痕要求**：候选复核的模型响应必须逐特征给出 `role_candidates_evaluated` 记录，
  其中至少一条 `source=full_text_rescan` 的全文角色重扫痕迹（包括「重扫未发现候选」的
  显式记录）；任何被复核的否定特征缺少该痕迹的，视同未完成复核，确定性降级 `uncertain`
  并写告警。

后续轮次新取得的 D2/D3 仍先单独执行本检查；若其中一篇完整覆盖，它成为新颖性对比文件，不再强行与原 D1 拼接。

## 7. 最接近现有技术与 gap

### 7.1 D1 选择

D1 候选必须先通过对应权利要求的证据和日期资格。确定性排序首先比较“高置信、可核查地确认
披露的必需特征数量”，数量更多者优先；仅在数量相同时再依次比较覆盖比例、证据完整度、
技术领域、技术目的/问题/效果、从该文献出发所需结构改动和稳定 document ID。选择因素包括：

- 有效且确定的特征覆盖；
- 技术领域；
- 技术目的、问题和效果；
- 从该文献出发所需的结构改动；
- 原文/附图定位和证据完整度。

文本或向量相似度只可用于发现阶段，不得覆盖上述 D1 排序。每次选择保存版本、候选集、每篇
确认披露数量、因素、选择理由和人工决定。

### 7.2 D1 重选

新轮次出现更合适候选时允许生成 `D1 v2/v3`。必须保留旧 D1、替换理由、旧/新覆盖矩阵和重新计算的 gap；不得原地覆盖历史。

### 7.3 D1、D2、D3 是分析角色，不是命中顺序

- “相似度最高”只能生成候选排序，不能直接产生正式 D1。正式 D1 必须已经取得真实内容、通过该权利要求的日期资格并完成单文献全限制比对，再综合技术领域、目的/效果、覆盖质量、所需改动和证据完整度选择。
- D2/D3 不是搜索结果中的第二、第三篇，也不保证分别来自第二、第三轮。它们是从所有已合格材料中，对当前 gap 提供最大有效增量并适合进入创造性组合的分析角色。
- 后轮出现一篇能够独自完整覆盖的文献时，该文献直接进入单文献新颖性分支；不能因为它原本被称为 D2/D3，就强行保留多文献组合。
- 多篇文献累计覆盖全部特征只能说明创造性组合具备了特征覆盖前提，绝不产生新颖性完整覆盖状态。

### 7.4 gap 类型

- `feature_gap`：特征未披露；
- `evidence_gap`：疑似披露但证据位置、全文、图像、译文或来源链不足；
- `date_gap`：公开时间、申请/优先权或公众可得性未核验；
- `combination_gap`：累计覆盖存在，但组合动机、明确启示、公知常识依据、相关技术问题、反向教导分析或可预期效果不足。

每个 gap 必须有版本、来源 disclosure、状态、解决它的文献/人工决定和关闭理由。

### 7.5 显而易见性预分析版本

I4-O 是 I4-C 与 I2-G 之间的强制模块，不是前端派生文案。每次 D1 版本、区别特征集合、目标
limitation 版本、日期合格语料、I4-S 规则或公知常识确认发生变化，都必须创建新的预分析版本；
旧版本保留但不得继续驱动查询。相互配合的区别特征允许组成一个 feature group，共享客观技术
问题、D1 启示、改造动机和检索路线，前端不得拆开后重复同一套占位结论。

## 8. 创造性组合分析

只有没有单篇完整覆盖时才运行 `I4-I`。组合中的每份普通现有技术材料都必须在关键日前公开；抵触申请候选不得进入组合。I4-I 必须消费最新 I4-O，并支持 `combination_basis = multi_document | d1_plus_common_general_knowledge | d1_internal_teaching_plus_routine_substitution`，不得为了满足旧接口虚构 D2。

I4-I 必须按创造性三步法消费当前 D1、D1 区别特征、模块九第 1—5 轮中全部当前版本且日期合格的 I4-S 结果，以及最新 I4-O。系统可以从全部候选中按“对区别特征的有效增量”选择实际组合文献，但不得在进入 I4-I 前只保留任意两篇补充文献，也不得因命中轮次靠后而忽略该文献；输出必须分别记录“已审阅语料”和“实际用于组合的文献”。

模块九部分或全部轮次失败、零命中或没有新增对比文件，不得阻止 I4-I。只要已有持久化 D1，I4-I
仍须使用首轮及当时全部日期合格、当前版本的真实 I4-S 语料输出；只有 D1 时允许
`combination_basis=unresolved`，结论必须为证据不足。输出同时携带逐轮错误台账（轮次、阶段、
错误码、安全摘要、受影响区别特征和证据限制），不得为凑足组合虚构 D2/D3。

三步法输出必须逐项闭合，而不是只给整组文献一个总判断：

1. 第一步固定 D1，并明确 D1 已公开的限制；
2. 第二步逐项固定 D1 未公开的区别特征及其实际技术问题；
3. 第三步对每项区别特征分别记录 D2/D3/其他现有技术或可引用公知常识的公开事实、相同结构角色/作用、具体技术启示、修改动机和修改路径、反向教导、效果是否可预期，以及每项所依赖的原文引文与位置。

“多篇文献累计覆盖全部限制”只是进入第三步判断的必要条件。只有每项区别特征的上述证据链均闭合、所有组合文献日期合格且不存在未解决冲突时，才允许输出“现有证据已形成缺乏创造性的完整证据链（供律师复核）”；否则只能输出“现有证据尚不足以证明不具备创造性”。后者不得改写为“目标专利具备创造性”或“目标专利有效”。多篇组合结果永远不得回写为单篇新颖性完整公开。

输出至少包含：

- D1 与 D2/D3 分别披露的特征；
- 仍未覆盖特征；
- 实际技术问题；
- 组合动机或明确技术启示及原文依据；
- 公知常识证据及其来源；
- 反向教导；
- 技术效果是否可预期；
- 结论所依赖的人工判断和未解决 gap。
- I4-O 每个 feature group 的预分析结论、搜索路线、证据/律师确认状态和最终复核结果。

D1+D2/D3 累计覆盖全部特征只是必要条件。D1+公知常识或 D1 内部启示+惯用替换路径也必须有可引用的 D1 锚点、改造动机、无反向教导和效果可预期依据；惯用手段只有模型预判且没有证据/律师确认时，`evidence_complete=false`。缺少组合理由时应创建 `combination_gap` 并进入下一轮，不得输出确定性的缺乏创造性结论。

## 9. 轮次结束与停止条件

### 9.1 成功停止

- `novelty_evidence_complete`：一篇合格文献完整覆盖全部限制；输出单文献新颖性 CC。
- `inventive_step_evidence_complete`：没有单篇完整覆盖，但合格组合覆盖、组合理由及必要分析证据完整；输出创造性累计 CC 和组合理由表。

这些状态表示“证据包达到自动流程标准”，不是行政机关或律师的最终法律结论。

### 9.2 非成功停止

- 无新增合格文献；
- gap 连续不变或没有实质缩小只作为下一轮改词的失败原因，不得在第五轮之前单独终止；
- 初始轮之后已经完成 5 个 gap 检索轮，或达到其他显式预算上限；
- 日期/优先权/依赖关系必须人工确认；
- provider 全部失败且没有批准的替代源（仅作为本轮错误；在第五轮前不得据此停止后续冻结轮）；
- 用户取消。

输出必须是 `partial`、`search_budget_exhausted`、`needs_human_review`、`failed` 或 `cancelled`，并保留当前证据和未解决 gap；不得把“未找到”改写成“具备新颖性/创造性”。

### 9.3 人工继续

自动创建契约使用 `max_gap_search_iterations=5`；兼容字段 `max_rounds` 只允许映射为相同含义，
不得把首轮计入五次。第五次 gap 检索结束后，不再自动创建第六次；系统必须保留未覆盖区别特征、
每轮失败原因和检索式，进入组合分析并生成 D1 + 默认 Top 5 的大 Claim Chart。人工继续只能
创建补充调查或显式 continuation iteration，不修改旧轮次，也不得把“检索五轮仍未找到”写成
权利要求具备创造性的结论。

普通 continuation 只允许选择仍存在未解决 gap 的非成功终态权利要求。调用方未显式选择权利要求时，系统也只能默认选择这些未解决项；不得默认包含 `novelty_evidence_complete` 或 `inventive_step_evidence_complete`。若请求显式包含任一成功终态，必须拒绝并提示另建补充调查，而不是静默跳过、重开或覆盖。

## 10. 模块职责与持久化边界

| 模块 | 单次输入 | 单次输出 | 禁止事项 |
| --- | --- | --- | --- |
| I0 | 已持久化调查状态 | 下一作业或终态 | 不做检索、日期或披露判断 |
| I1 | 不可变源文件 | 中立事实快照 | 不总结保护范围或作法律判断 |
| I1.5 | 独立 claim、专利级日期事实 | 关键日与资格 | 不让模型决定日期资格 |
| I2 | claim、首轮目标专利事实 | 固定五类首轮查询计划 | 不读取对比文献，不直接调用 provider 或下一轮 |
| I2-G | 最新 I4-O 未解决搜索目标及冻结版本绑定 | 一次生成的第1—5轮 `gap_query_matrix`：每轮全部未解决区别特征的逐特征主查询、策略、人工复核标记和附加补证计划 | 不重算预分析；不得按轮临时重写；不得因人工复核或模型预判取消未闭合特征的主查询；不直接调用 provider |
| I3-P/NPL | 单个查询计划 | lead 与原始响应 | 不把题录当全文；EPO 不接收智慧芽检索式 |
| I3-F | 同案搜索 run、目标发明画像 | 唯一取文候选、排除/重复清单与审计 | 不读取决定书答案；不因字面未命中排除；不作日期、披露或法律结论 |
| I3-E | lead/原始文件 | 文献版本、`ReadablePatentDocumentV1` 与证据阶段 | 专利 lead 按智慧芽标识先调用 EPO，明确无覆盖时才以同一候选调用 P020；不伪造文件、日期、图片或可分析全文 |
| I4-S | claim + `analysis_ready` 单文献版本 | 整体机构图与单文献覆盖矩阵 | 不拼接文献判断新颖性，不以词面或功能相同代替结构关系 |
| I4-C | 合格单文献矩阵 | D1 版本与 gap | 不以相似度单独决定 D1 |
| I4-O | D1、区别特征、目标作用/效果、合格语料 | 显而易见性预分析版本与补证分流 | 不把区别特征自动等同于必须检索；不把模型惯用手段预判冒充完整证据 |
| I4-I | 最新 I4-O、D1、组合候选/公知常识、gap | 三类路径的最终组合分析 | 不让抵触申请进入创造性；不虚构 D2 |
| I5 | 已持久化审计事实 | 模块10人类可读分析、相似度 Top 10 横向矩阵、全部逐篇 CC 与不可变报告快照 | 不从空数据合成成功报告；不以待确认证据提高相似度；不把其他案件或历史批次混入当前报告 |

每个模块运行必须有：`module_run_id`、模块/契约版本、claim/iteration 关联、输入工件哈希、requested/effective mode、实际 provider/model、开始/完成时间、状态、错误和输出工件哈希。

## 11. 模块实验室模式

律师使用的 `/test/module-lab` 把底层模块组合成十一个可分别测试的业务阶段：①读取目标专利；
②确定关键日；③总结核心发明点；④生成首轮检索词；⑤首轮检索与证据核验；⑥单篇新颖性
比对；⑦选择 D1 与冻结区别特征；⑧显而易见性预分析；⑨进一步检索与补证循环；⑩创造性组合分析；
⑪三步法文字分析、相似度 Top 10 总表与全部逐篇比对。每个阶段必须分别保留“当前真实案件”和“内置示例”入口、独立运行状态、本次实际
输入和可读输出。第⑧阶段独立运行 `I4_O_OBVIOUSNESS_PRECHECK` 并逐特征/特征组展示真实分析；第⑨阶段首次运行即生成并冻结完整五轮 `gap_query_matrix`，页面按 `gap_search_iteration` 展开一至五轮并默认折叠，展示既有语料复用决定、未覆盖区别特征、五轮策略和实际查询计划；在同案前序事实
齐备且计划包含可执行查询时，必须继续执行本轮 I3 检索、I3-F 候选清理、I3-E 取文、日期资格
与新取得文献的 I4-S 覆盖复核；不得把成功的 `I2_GAP_QUERY_PLAN` 单独显示为第⑨阶段已经完成。
查询真实返回零候选，或候选清理后没有可取全文时，可以以保留完整执行审计的零文献结果完成
当前轮；只要仍有未由可引用证据关闭的区别特征，第⑨阶段就自动排入并执行矩阵中下一轮对应行，
不再现场生成或调整关键词；一旦存在 `analysis_ready` 新文献，则该文献
没有 I4-S 终态前第⑨阶段不得显示成功。
第⑨阶段必须把轮次、查询、文献处理和 I4-S 进度持久化，页面刷新、Portal 重启或轮询中断后从
同一批次恢复；只有全部区别特征关闭或第五轮收口后才能把整个阶段标为完成/耗尽。五个 gap 轮不是五个固定
顶层模块。原「检索方案」模块自 2026-08-04 起拆分为两个业务模块：模块三
「总结核心发明点」调用 `I2_INVENTIVE_PROFILE`，只输出发明画像（`invention_summary`
核心发明点总结、发明点区别特征及其绑定的技术特征），不生成检索式；模块四「生成检索关键词」
调用 `I2_QUERY_PLAN`，编译检索关键词/查询组合。模块四 live 模式的输入固定为同案同独立
权利要求最新成功的模块三运行输出（发明画像 + limitations），不再重新读取专利摘要、说明书、
附图或权利要求原文；2026-08-05 起按用户进一步决定（修订此前「免模型确定性重编译」）：
模块四每次运行都必须以该画像为输入重新调用 GLM，由模型按多分辨率检索线角色分析并提出
检索关键词/查询组合，模型提案继续经过全部既有确定性守门（三类任二、中文关键词 ≤6 字
原子化、首轮 5 条上限优先级裁减），第二次模型响应仍不合规时才允许用画像已冻结事实确定性
组装兜底并保留完整审计；输出来源标记为 `module3_profile_live_model` 并携带
`source_plan_run_id` 溯源到模块三运行。没有对应成功模块三运行时模块四明确失败
（`LAB_I2_PROFILE_REQUIRED`）并提示先运行模块三，禁止静默回退。模块四该次 GLM 调用为
纯文本子任务，经显式 `allow_text_only` 放行且模型仍为 GLM-4.6V，不构成静默纯文本降级。
2026-08-02 禁复用守门（`LAB_I2_CACHED_PROFILE_FORBIDDEN`）仍只拦截 `plan_queries`
引擎内部缓存复用；`recompile_initial_query_plan` 免模型重编译仅保留给正式 release 与
离线脚本。manual/fixture 模式与正式 I0 流水线的 I2 行为不变。每个业务模块只提供
“当前真实案件”和“内置示例”两个主操作；真实案件输入由服务端从 Investigation 和已持久化
前序事实生成，fixture 使用版本化夹具。原始 JSON、provider、底层 module code 和 manual
模式只保留在高级技术入口或底层 API，不得要求律师填写。

I2-G 的状态字段必须区分三组事实：`covered_difference_feature_ids` 仅包含已有合格语料或 I4-O
完整证据真正关闭的特征；`uncovered_difference_feature_ids` 保留全部仍未解决特征；
`allowed_gap_feature_ids` 在当前版本必须包含全部未由可引用证据关闭且未耗尽五轮的区别特征，
`human_review_feature_ids` 只是其中仍需律师判断的并行标记，不能再从允许检索集合中扣除。
只要 `uncovered_difference_feature_ids` 非空且尚未完成第五轮，`search_required` 必须为 true，
并且每个未覆盖 feature 至少有一条主查询；只有确已全部关闭或第五轮耗尽才允许零查询收口。
I2-G 输出还必须在顶层冻结当前 `closest_document_id`，Portal 对旧运行可依次从 I4-O、区别特征
和 I4-C 恢复同一 D1。

I2-G 的模型查询必须使用 gap 的 purpose、role、variant、objective 和冻结的允许特征集合；模型
在收到一次精确守门反馈后仍输出首轮组合时，系统丢弃全部不合规查询，但不得因此把整个模块
标记为无输出。允许以模块三画像和 I4-O 已冻结事实作确定性恢复：每个允许自动检索的区别特征
分别建立一条短检索线，只取一个可追溯的核心含义锚点，并仅把同一原子概念的同义/合理上位词
放在同一 OR 组；禁止把多个区别特征全文或一个复合限定中的所有构件串成大量 AND。逐特征主线
是最低预算，因此当未覆盖区别特征超过五项时，本轮查询总数必须至少等于未覆盖特征数；首轮
固定五线的“五条上限”不得套用到 gap 轮。完成逐特征主线后，才可在配置允许的附加预算内补齐
patent ordinary、NPL ordinary 和 patent conflicting-application 通道，完整保留模型响应、拒绝
理由、旧表达、逐特征失败原因、改写方向和确定性恢复警告。

确定性守门必须在 provider 执行前核验：普通专利主线数量严格等于本轮未解决区别特征数量；每个
feature ID 恰好出现一次；每条主线恰有一个 feature ID、两个 OR 组和一个组间 AND；两个 OR 组
均至少包含一个中文词和一个英文词；客体组不含目标专利完全相同的中英文类别名称。模型输出只可
提供可追溯词项候选，最终主线一律由该守门重新编译。任一必需双语概念组无法从冻结事实或本轮
模型分析形成时，本轮计划明确失败并保存缺失项，不得静默退化为目标原类别、单语查询或裸泛词。
第二轮起每个 feature 的主线还必须相对该 feature 的上一轮冻结主线实质更换至少一个客体或特征
概念；该检查在五轮矩阵生成时一次完成，最多五轮的上限不变。

律师模块九对外仍是一个业务模块。单轮内必须完整执行
`I2-G -> I3 检索 -> I3-F -> I3-E/日期资格 -> 新全文 I4-S`；本轮进入终态后自动执行既有矩阵中
下一冻结轮次，不再调用模型临时改写检索词。若本轮计划、检索、取文、日期资格或 I4-S 部分/全部
失败，成功文献、检索命中、全文和日期资格均保持不变，失败文献不得计作覆盖证据，相关区别特征
继续保持未覆盖；该轮保存 `failure_reasons` 后自动推进，不再停在 `round_partial` 等待律师选择。
历史批次的“仅重试失败文献/带失败继续”接口只作兼容恢复，不是新批次的自动流程。Portal 必须按轮分别显示本轮计划数、实际
检索数、命中、全文、日期资格及 I4-S 成败，累计统计另列，禁止把多轮累计检索数与单轮计划数
拼成类似“6/2”的口径。

模块九顶部必须一次展示五轮矩阵摘要，默认全部折叠；轮次状态至少区分 `pending`、`running`、
`completed`、`partial`、`skipped_feature_resolved`，文献处理至少区分 `new`、`reused`、`analyzed`、
`failed`。点击某轮只能执行当前允许的下一轮；后续轮不可越过尚未收口的前序轮。

模块九的批次作用域固定为 `investigation_id + claim_investigation_id + batch_id`。律师界面必须
把操作分开：没有批次时“开始第 1 轮”；已有批次时可以“恢复/查看当前批次”；新批次自动推进
冻结后续轮，不显示必须由律师逐轮放行的“开启下一轮”。已有批次不妨碍律师
另行选择“重新开始第 1 轮”；该操作创建新的 `start_mode=fresh` 批次，从 gap iteration 1 读取
当前版本 I4-C/I4-O 的 D1 与未解决区别特征，不删除、不覆盖旧批次。旧浏览器时代的 module9
cursor 只能通过显式 `resume_legacy` 兼容入口继承，不能让“开始第 1 轮”暗中跳到后续轮次。
切换目标专利或独立权利要求时，Portal 必须取消旧批次轮询、清除 URL/内存中的模块六/九批次
绑定，并按新作用域恢复最新批次；服务端和页面都要拒绝 investigation 或 claim 不一致的批次，
不得仅因属于同一用户就跨案件复用。模块九仍不直接从原始目标专利推导 D1；当前案件缺少模块七
和模块八的同版本持久化事实时，第 1 轮应明确提示完成前置阶段，而不是借用上一案件结果。

旧案件的 limitation 行若早于双语字段，不要求重跑前七个模块：I2-G 应优先恢复同案同独权最新
成功 I2 运行中与真实 feature ID 相交的目标侧画像/双语词族；仍缺词时才触发只做查询语言改写的
窄模型任务，该任务不得判断覆盖或法律结论。跨轮比较按 OR 成员集合而非显示顺序计算；同一组词
仅改变排列顺序不构成实质改写，系统须选择成员集合实际不同的双语子组或新词组。

`existing_corpus_reuse` 中的“缺少可复用版本键”是未覆盖理由，不是错误终态：它表示旧语料的
文献版本/内容哈希、目标 limitation 版本、日期资格 revision、I4-S run/rule 尚未形成完整同一
缓存身份，因此系统禁止直接宣称该区别特征已被既有证据覆盖。对应特征必须继续留在
`uncovered_difference_feature_ids`，并按 I4-O 路由进入本轮真实补检或律师复核。模块实验室
应把该信息显示为复用审计说明，不得用它替代新检索和 I4-S 的执行结果。

### fixture

- 只使用固定、版本化夹具；
- 输出必须带 `simulated=true` 和 `fixture_id`；
- 没有真实图片时图片使用数必须为 0；
- 不得标记为真实检索或合格对比文件。

### manual

- 允许用户导入真实材料、日期声明和人工判断；
- 原文件仍需快照和哈希；
- 人工提供的事实必须标记 `human_supplied`；
- 日期未核验时不得自动升级为合格证据。

### live

- 只能调用配置并批准的真实 provider 和 GLM-4.6V；
- 禁止 `manual` provider、`fixture_output` 和客户端伪造的 stage/hash/eligibility；
- 输出必须记录 `network_used`、实际 provider、模型、来源和失败。

完整 I0 正式调查只能使用 live 或显式人工导入的真实证据；fixture 只用于模块契约和回归，不能冒充正式调查。

## 12. 人工复核操作

必须支持：

- 确认或改定专利级优先权和关键日（改定结果自动适用于全部范围内的独立权利要求）；
- 修正依赖展开或特征拆解；
- 导入材料和日期证据；
- 改选 D1 并填写理由；
- 关闭/重开 gap；
- 取消、重试失败作业；
- 查看初始轮和最多五个 gap 检索轮结果后显式创建补充调查或继续轮次。

所有操作都创建新版本或审计事件，不能原地抹除模型或规则历史。

### 12.1 人工复核不是直接修改 checkpoint

人工事实的权威来源是关系表中的不可变版本和已冻结工件；`workflow_state`
checkpoint 只是可重建缓存。人工操作不得直接改写 checkpoint 中的
`documents`、`date_qualifications`、D1 或 gap，也不得让旧 worker 在复核后用旧
checkpoint 覆盖人工决定。

每次人工操作必须在同一个事务中：

1. 校验资源属于当前 Investigation，并且目标 claim/document version 属于同一调查；
2. 先按 `idempotency_key` 查找既有命令：同 key、同请求哈希返回原响应，同 key、
   不同请求返回 `409`；
3. 校验调用方提交的 investigation、claim 和 review revision；
4. 写入不可变的 typed revision、`human_review_action` 和事件；
5. 增加 `review_revision` / `state_version`，标记受影响派生结果失效；
6. 创建唯一的 `human_review_apply` module run/job，或在无外部调用的纯确定性操作中
   以同一 CAS 事务完成关系事实重建；
7. 重算完成后再提交新 checkpoint 和当前版本报告。

只有在 Investigation 没有 queued/leased/running 的 I0、I5 或
`human_review_apply` 作业，且最近 iteration 已进入终态时才接受人工复核命令；否则
返回 `409 REVIEW_NOT_QUIESCENT`。成功终态 claim 不接受普通复核重开，补强或纠错必须
创建关联的新调查。

### 12.2 不可变文献内容与引用

`document` 只表示规范化文献身份；每次取得的真实字节、解析结果、来源快照和内容哈希
属于不可变的 `document_version`：

- 同一 document、同一 SHA-256 是幂等重放；
- 同一 document、不同 SHA-256 创建 `version_no + 1`，不得更新旧版本内容；
- document source、日期事实、日期资格、I4-S disclosure、D1 和组合必须明确引用
  `document_version_id`；
- 报告必须显示实际使用的文献版本和哈希，旧 I4-S/D1 不得静默指向后来取得的文件。

人工导入必须冻结真实文件或合规网页快照，校验真实路径、MIME、大小、SHA-256、来源和
获取时间。`human_supplied` 只说明提供方式，不自动表示日期已核验、内容相关或已成为
`qualified_evidence`。

### 12.3 命令日志与并发控制

`human_review_actions` 至少保存：action type、目标、actor、理由、请求哈希、
idempotency key 哈希、命令序号、基础/结果 investigation 与 claim state version、
review revision、状态、module run/job、失效范围和重算摘要。

所有命令共享以下并发字段：

- `contract_version = v1`；
- `expected_investigation_state_version`；
- 所有受影响 claim 的 `expected_claim_state_version`；
- `expected_review_revision`；
- 在一次用户提交意图内保持不变的 `idempotency_key`；
- 非空人工理由。

涉及多个 claim 时按稳定 UUID 顺序加锁。旧版本、旧 limitation hash、旧 qualification、
旧 D1 或旧 gap fingerprint 均必须返回 `409`，禁止最后写入者静默覆盖。

### 12.4 人工复核读取契约

`GET /v1/investigations/{id}/review-context` 返回服务端计算的当前上下文，至少包含：

- investigation/claim 的 state version 与 review revision；
- 是否 quiescent、是否存在待重算结果；
- 每份 document 的当前 document version、不可变版本历史和内容哈希；
- 每项 claim × document version 的最新日期事实和资格版本；
- 可选 D1 候选、当前 D1 及其依据版本；
- 每个 `gap_key` 的最新版本、状态和 lineage；
- 未完成的人工 action。

Portal 不得从全量历史行自行猜测“当前版本”。

### 12.5 人工材料导入

正式服务使用：

`POST /v1/investigations/{id}/human-reviews/evidence-imports`

请求除公共并发字段外，包含规范文献身份、文献类型、题名、语言、目标 claim 集和一个
服务器可验证的来源。Portal 浏览器只能提交绑定 user + session + environment + SHA 的
上传收据；Portal 服务端校验并消费收据后，才可向固定环境后端传递受允许根目录约束的
真实路径。浏览器不得传 environment、actor、后端路径或任意本机路径。

服务端冻结文件、创建/复用 document identity、追加 document version、source、
evidence import 和 action，并为每项目标 claim 分别运行日期规则。日期证据不足时只生成
`date_gap` / `needs_human_review`，不得把导入动作本身当成资格确认。导入的新文献版本必须
执行新的 I4-S；不得复用其他文献版本的披露矩阵。

### 12.6 候选文献日期确认

正式服务使用：

`POST /v1/investigations/{id}/human-reviews/document-date-confirmations`

请求必须绑定 `document_id + document_version_id`、目标 claim 集、上一资格版本、日期事实、
日期通道以及逐项日期证据的来源、locator 和工件引用。客户端不得提交
`novelty_eligible`、`inventive_step_eligible` 或最终资格类别；服务端只能用已确认的目标
claim 关键日/公开日和确定性日期引擎生成 append-only qualification vN+1。

确认、排除和重新打开复核都保存日期事实 revision 和原因代码。日期变化使该 claim 下的
新颖性停止、D1、gap、组合和当前报告失效；相同 document/limitation version 的既有
I4-S 可以重用，但重算提交前必须重新校验输入哈希。

### 12.7 人工 D1 与 gap 决定

人工 D1 只能从 `review-context` 返回的可选候选中选择，并绑定当前 qualification revision、
完整 I4-S 输入/输出哈希以及当前 limitation-set hash。服务端再次验证：创造性日期合格、
非抵触申请、完成所有必需限制的单文献比对，且不存在任何合格单篇完整覆盖。D1 改选追加
新版本并使当前 gap/组合/报告失效，不覆盖旧选择。

gap 的 close/reopen 必须绑定最新 gap id、version 和 fingerprint，并追加同 lineage 的新
版本。只有 `resolved_with_evidence` 可以计入证据完整；`waived`、`stop_search` 或
`duplicate` 只能停止追索，不能制造新颖性/创造性成功结论。`date_gap` 不能通过普通 close
解决，必须走日期确认命令。

### 12.8 checkpoint 恢复与报告失效

checkpoint 保存 `review_revision` 和 `last_applied_review_action_seq`。worker 启动、人工继续
开始、I5 开始和报告生成前都必须比较关系事实与 checkpoint revision；不一致时从当前
document versions、最新 qualifications、可复用 I4-S、当前 D1 和最新 gap lineage 重建，
禁止信任旧缓存。

人工 action 增加 investigation state version 后，旧报告只能通过显式 snapshot id 查看。
默认 current-report 接口只有在报告的 `source_state_version` 等于当前 investigation
`state_version` 且 review revision 一致时才返回报告；否则返回
`202 REPORT_PENDING`。结果页必须显示待重算，导出必须拒绝生成看似当前的旧报告。

Agent 与模块实验室执行相同合同并固定到唯一无效后端；它们只在页面交互和自动/分步推进方式上
不同。上传收据继续按用户、session 和资源 owner 隔离，而不是按前端页面隔离。actor 由已鉴权
Portal 服务端注入；浏览器字段不得覆盖。

每次 Agent 分析只有一个 `analysis_session_id`，并解析到唯一的 `investigation_id`。Agent 是普通
用户的唯一任务视图：当前事项、逐独立权利要求结论、证据边界和全部人工确认必须直接显示在消息
工具卡或 Agent 内弹窗中，不得要求普通用户跳到 `/invalidity/results` 才能理解任务。历史结果页
可以保留为兼容深链，但不是新任务的正常出口。

`/test/module-lab?session=<analysis_session_id>` 是管理员对同一任务的诊断投影。服务端必须先校验
approved admin，再由 session 解析 investigation，读取同一份 claim、module run、job、错误和报告
快照。打开、刷新或轮询该视图不得创建/复制 investigation，不得恢复批次或创建 module run，也不得
改写 session 状态；需要手动重跑时，管理员必须退出只读诊断并显式发起带新审计记录的实验运行。

正式 Agent 到达 `partial` 且仍有 open gap、当前迭代尚未执行完第 5 个 gap 轮的调度检查点时，
工具卡必须弹出下一轮确认并显示 30 秒倒计时。确认请求只提交 investigation `state_version`；服务端
重新读取 owner-scoped tool/session/investigation/claim，选择仍为 `partial` 且位于上限内的独立权利
要求，每次仅创建一个后续轮，并以 tool run + state version 形成幂等键。用户显式确认立即执行；
倒计时从该 checkpoint 的持久化 `updated_at` 计算，刷新不重置，届满时自动提交。状态已经前进、
claim 已收口或达到第五轮时不得重复创建。`needs_human_review` 及关键日、日期资格、D1、证据导入、
gap 放弃等会改变法律事实或证据资格的动作只在 Agent 中弹出人工入口，不适用超时自动确认。

## 13. I5 报告契约

终态必须生成版本化、不可变的 `ReportDataV1` 快照及 SHA-256。至少包含：

- 调查、完整目标专利快照、独立权利要求范围和逐独立权利要求关键日；
- 单文献新颖性 CC；
- D1 当前版本与历史；
- 创造性累计覆盖和组合理由；
- 模块11第一部分：从当前模块10结构化 I4-I 结果确定性转写的人类可读分析。论述顺序至少包括
  D1、区别特征、实际技术问题、补充文献或可引用公知常识、相同作用、技术启示、修改动机与
  具体路径、反向教导、效果可预期性和证据结论；不得调用模型补写，不得增加模块10没有的事实；
- 模块11第二部分：以独立权利要求全部技术特征为纵轴、当前案件相似度最高的最多 10 篇已完成
  I4-S 文献为横轴的矩阵。相似度首先按已确认披露特征数/覆盖率排序，`uncertain` 不计为披露，
  再按确定性评价完整度和稳定文献标识排序；不足 10 篇时按实际数量显示。每格至少区分明确或
  必然隐含披露、未披露、待确认和分析失败/未完成；文本或向量相似度不得覆盖该排序；
- 模块11第三部分：保留当前案件全部已检索且已进入逐篇分析的对比文件与独立权利要求全部特征
  的逐篇 CC，显示原文、位置、结构对应和理由，不得只保留 Top 10；
- Agent 运行过程卡只展示来自持久化阶段状态的可核验工作动态、当前事项、十一模块进度、错误和人工
  动作，不得把模型内部隐藏推理伪装成可审计事实。模块11完成后，Agent 必须在过程卡之后另起一条
  独立结果消息消费该不可变 DTO，并默认展开显示第一部分律师文字和第二部分 Top 10 横向矩阵；不得把
  完整结论继续嵌套在过程卡内，不得只投影文献数、披露数或一句摘要，也不得要求普通用户跳转测试页
  查看。第三部分通过同一 session 的 Excel 导出交付：除总览和审计表外，为当前案件每篇已进入逐篇
  分析的对比文件分别生成一个 Claim Chart Sheet，并提供逐篇索引；旧 session 只按既有快照重新呈现
  和导出，不改写历史调查、模块运行或审计记录；
- I4-I 内部组合证据仍可保留 D1 + 默认最多 5 篇按区别特征有效增量选择的大 Claim Chart；该表
  与模块11第二部分的相似度 Top 10 总览用途不同，不得互相替代；
- 四类 gap；

## 14. 安全与隔离

- source path 只能位于显式允许的上传根目录，解析真实路径后拒绝符号链接逃逸。
- source URL 仅允许 HTTP(S)；DNS 和每次重定向都拒绝 loopback、私网和链路本地地址，并设置 MIME、字节和重定向上限。
- 唯一无效后端必须校验 Bearer token；配置缺失时 fail closed。
- Portal 优先使用中性配置 `INVALIDITY_API_URL/API_TOKEN/UPLOAD_ROOT`；迁移期可从既有
  `INVALIDITY_TEST_*` 显式解析同一值，但不得回落 5109、另一 schema 或另一工件根。
- Agent 与模块实验室均须校验用户/session/资源归属，不能让获准用户互相读取调查。
- `/test/module-lab` 及其按 Agent session 读取同任务诊断数据的接口只允许 approved admin；普通
  用户只能在 Agent 中查看自己任务的可理解结果和完成必要确认。
- 当前唯一服务固定为精确 `127.0.0.1:5209`；5109 和历史 prod release 不接受新请求。
- 凭据、鉴权头、内部异常、私有路径和敏感原始响应不得进入前端、普通日志或报告。

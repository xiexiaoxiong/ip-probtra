# 专利无效检索系统（唯一后端；目录名保留历史 test 标识）

这是与既有商品侵权流程隔离的专利稳定性/无效检索唯一后端。Agent 自动分析与十一模块实验室都调用本服务；`test` 目录名、5209 和 `invalidity_test` 仅是历史运行标识，不再表示存在另一套正式业务后端。服务共享模块一提供的中立专利事实，但会在调查创建时制作不可变快照；查询、文献、日期资格、单文献覆盖、最接近现有技术、区别特征、组合分析和报告全部写入同一 schema。

产品边界以根目录 `PROJECT_CHARTER.md` 2.40 为准，逐独立权利要求状态机、普通现有技术/抵触申请双日期通道、D1 区别特征循环、四类 gap、provider 能力契约、报告和验收要求以 `docs/invalidity/WORKFLOW_SPEC.md` 3.65 为准。模块一继续冻结全部权利要求事实，当前自动调查只处理独立权利要求。

## 逻辑模块

- `I0`：持久化编排、作业租约、恢复与逐独立权利要求停止。
- `I1-T`：测试实验室专用目标快照准备；完整解析并冻结目标专利著录日期、摘要、全部权利要求及依赖关系、说明书章节、分页正文和全部附图，不启动完整 I0。后续检索仍只处理独立权利要求。
- `I1.5`：依赖展开、优先权/申请日关键日和文献日期资格。
- `I2`：通读完整专利后建立构件角色、拓扑、运动/状态、控制和技术作用的通用机构模型，并把首轮普通现有技术专利查询固定为五组：申请人+客体、标题客体+说明书核心发明点、分类号+说明书核心发明点、说明书客体+核心发明点+效果、标题/摘要客体+说明书功能效果；每组至多一条、总数不超过五条。
- `I2-G`：在 D1 选出后冻结区别特征的目标内容、结构角色/关系和技术作用；模块九开始时一次生成、逐轮交叉校验并冻结五轮矩阵，随后自动执行各冻结轮次，不再临时重写关键词。每个尚未由可引用证据关闭的区别特征在每轮至少一条主检索线；五轮固定按“相邻产品+直接结构 → 优先有效上位、必要时合适下位产品+结构族 → 同功能产品+动作/角色 → 子系统部件+关系/路径 → 类比领域+原理/效果”递进。第 2 轮必须保存上下位选择理由；目标客体已经过宽、继续上位只能得到泛词时，可选择承担相同用途/技术角色的下位产品。客体组和特征组都必须相对上一轮实质换族，删词、换序、只换译法或在同一词后替换“装置/结构/机构”均不得通过。exact 客体只包括目标实际等同类别；混合词组会移除 exact 词并留痕，剩余双语上位/邻近/合适下位词继续编译。新文献 I4-S 后按特征关闭，未来矩阵行标为 `skipped_feature_resolved`。
- `I3-P`：全球专利候选发现。
- `I3-NPL`：论文等非专利材料候选发现。
- `I3-F`：在所有候选发现完成后、全文取文前合并重复版本，并保守排除题录已经足以证明的明显跨领域候选。
- `I3-E`：内容、日期、来源和文件哈希标准化；EPO 结构化 XML 优先，PDF 文本其次，扫描 PDF 在持久化后台作业中逐页 OCR，并生成可缓存的可读 JSON/Markdown。
- `I4-S`：一项权利要求对一份文献的图文披露矩阵；只有目标专利完整机构上下文与 `analysis_ready=true` 的完整可读对比文件同时具备时才可进入。判断以构件角色、适用的流路/能量路径、连接拓扑、运动/状态和控制关系为中心，允许名称、零件数量、拆分方式和外形不同，也允许一个集成构件承接多个目标特征；不以逐词相同或仅功能相似代替结构披露。
- `I4-C`：先按已确认相同技术特征数选择最接近现有技术，再保存区别特征和版本历史。
- `I4-I`：按创造性三步法消费当前 D1、D1 区别特征、最新 I4-O 和模块九最多五轮的当前日期合格 I4-S 语料；逐区别特征核验补充公开、相同作用、技术启示、修改动机/路径、反向教导和效果可预期性。模块九全部错误或没有新增文献时仍使用现有真实 D1/语料输出证据不足结论，并附逐轮错误台账，禁止虚构 D2/D3。
- `I5`：三部分律师报告数据：模块10三步法结果的人类可读文字版；按本次 I4-S 确认披露特征数排序的相似度 Top 10 横向矩阵；以及当前案件全部对比文件的逐篇 CC。I4-I 内部仍保留 D1 + 默认 Top 5 的组合增量表，但不把它冒充相似度 Top 10。

初始轮不计入 gap 预算。首轮未找到单篇完整覆盖后，系统最多执行 5 个 gap 检索轮；每轮都按
“I2-G 复用检查/逐个剩余差异生成主查询 → 检索 → 清理 → 取文或版本一致复用 → I4-S → 逐特征
重新检查”推进。每个未闭合区别特征每轮至少有一条主查询，公知常识/NPL/抵触申请/组合启示线
只能作为附加通道。任一新文献单篇覆盖全部限制或全部区别特征已经覆盖时立即停止新增检索；
否则系统保存本轮失败原因，并执行矩阵中下一轮已经冻结的客体/特征词。每个计划与
查询都保存 `gap_search_strategy` 及可读标签；当前轮词族不足时本轮明确失败并留痕，禁止回退旧词池或把
旧词删减/换序后伪装成新一轮，但该错误不得阻断后续冻结轮。第五轮仍未覆盖时
标记 `gap_search_exhausted`，继续保留组合分析和大 Claim Chart，不输出“权利要求具备创造性”。

## 主要 API

- `POST /v1/investigations`：创建调查并制作输入快照。
- `POST /v1/investigations/{id}/start`：启动持久化工作流。
- `GET /v1/investigations/{id}`：查询总状态。
- `GET /v1/investigations/{id}/claims`：查询逐权利要求状态。

- `GET /v1/investigations/{id}/report-data`：读取结果页/导出所需数据。

- `GET /v1/lab/module-runs/{id}`：查询模块运行结果。

- `GET /health`：健康检查与隔离配置摘要。

测试解析兼容服务可在另一个终端加载同一份 `.env.test.local` 后运行 `scripts/parser_http_run.sh`。两个隔离启动脚本都要求测试配置完整，缺失即退出，不会回落 `IP-protral/.env.local` 的正式端口或凭据。

当前及后续 I3-P 专利候选发现统一使用智慧芽（Patsnap）P002；EPO OPS 不接收 I2 检索式，也不作为候选检索回退。P002 返回 `patent_id + pn` 后，I3-E 先把规范化公开号交给 EPO OPS，依次核验官方题录、全文能力和 `FullDocument` 页面；EPO 返回公开号与智慧芽候选不完全一致时立即拒绝。成功时逐页取得官方 PDF、校验每页、合并为完整 PDF、冻结原始 OPS 响应 bundle，并分别记录发现源 `patsnap`、取文源 `epo_ops`、页数和 SHA-256。

只有 EPO 对该精确公开号明确返回 404、无文献、无全文或无 `FullDocument` PDF 时，系统才按原 P002 候选的同一 `patent_id + pn` 回退智慧芽 P020；EPO 鉴权、网络、超时、429、5xx、解析错误、身份冲突或多结果歧义不会触发回退。P020 必须立即下载真实 PDF，校验 MIME、`%PDF`、可解析页数、字节数和 SHA-256，并冻结 metadata、调用审计和 PDF。两边都无同号文献时才保留 lead/evidence gap，始终不换成同族或相似标题文献。

面向当前 P002 能力的测试入口是 `http://127.0.0.1:3001/test/invalidity`，律师日常测试入口
是 `http://127.0.0.1:3001/test/module-lab`。链路固定执行
`I1_TARGET_SNAPSHOT → I2_QUERY_PLAN → I3_PATENT_SEARCH`：先把测试上传文件解析成不可变
目标快照，随后由 `glm-4.6v` 通读标题、摘要、全部权利要求、说明书和冻结附图，形成
`invention_search_profile`，再为独立权利要求生成分角色、分字段检索方案。

第一轮只执行事实齐备的固定五组检索线：

- `applicant_plus_object`：唯一申请人/专利权人 `AN` + 客体 `TTL OR ABST`；P002 原始前 10
  和响应工件先冻结，再由本地结果层按规范化公开号主体排除目标专利及 A/B/U/S 变体并留痕；
  申请人缺失或歧义时跳过留痕；
- `title_object_plus_desc_inventive`：标题客体 + 说明书核心发明点；
- `classification_plus_desc_inventive`：至多两个客体相关分类号 + 说明书核心发明点；
- `desc_object_plus_desc_inventive_plus_effect`：说明书客体 + 核心发明点 + 技术效果；
- `title_keyword_object_plus_desc_function`：标题/摘要客体 + 说明书功能效果。

第①组以 applicant+subject 满足守门，其余组按真实 feature、subject、classification 三类
任二守门；该充分性只在 I2 生成/编译阶段校验一次。I3 按同案同独权成功计划的
`query_plan_run_id + query_id + provider_expression` 精确回读冻结组合并原样发射，不再重复套用
旧通用单条检索式守门；临时、跨案或表达式不一致输入仍拒绝。每个 OR 组最多 5 个成员，截断
时保留具体中文词、同组核心含义/合理上位中文词和已冻结的跨语言对应词；中文关键词继续执行
≤6 字原子化。具体客体、构件和作用词不得被宽词替换，例如具体喷水车客体可在同组并列喷水车/
玩具车等同类基础类别，具体供水管与吸水结构可在各自同组并列供水/吸水；宽词不另起第六条，
也不得退化成“装置、结构、部件、系统”等裸泛词。每组按
`query_id/query_variant` 建立独立 P002 run；零命中是成功事实，固定五组不执行 compact
fallback，也不自动生成旧多分辨率、NPL、引证或效果辅助首轮线。

I2 第一次模型输出没有形成固定五组所需画像事实和合规计划时，不向律师返回失败，而是把
逐条拒绝原因反馈给模型继续生成。连续不合规时，确定性编译器只使用冻结客体、唯一申请人/
公开号、真实 feature、功能效果词和分类候选组装缺失固定组，再经过同一守门；每次模型尝试分别保留原始响应和
拒绝原因，不能覆盖历史。

D1 选定后的后续轮统一由 `I2_GAP_QUERY_PLAN` 负责。模块九先连续形成五个不同语义视角的计划；
某轮最终未通过守门时冻结该失败行并继续生成/执行其他轮，后续轮直接消费同一矩阵版本。该模块先检查当前版本既有 I4-S 语料能否
以相同结构角色/关系和作用覆盖 D1 区别特征，再为每个仍未覆盖的 feature 至少生成一条主查询；
人工复核、模型预判惯用手段或缺少复用版本键都不能让未闭合 feature 变成零查询。上一轮失败
原因和旧检索式会进入下一轮 prompt，全部原样重复会被守门拒绝；新轮必须依次采用固定五轮
语义策略，不得把同一词池换序、换一个同义词成员或删减限定冒充新检索角度。若既有语料已经以
可引用证据覆盖全部区别特征，本轮计划明确
保存 `queries=[]`，不调用检索 provider，但继续运行组合评价并更新 D1 + Top 5 大 Claim Chart。
首轮之后最多执行五个 gap 轮，旧 `I2_QUERY_PLAN` 不再参与后续轮。

律师模块九把批次入口明确分开：没有当前批次时可“生成并执行五轮”；已有批次时恢复
五轮矩阵和当前轮次并继续自动推进；律师也可随时另建一个不覆盖历史的 fresh 批次重新
生成矩阵并从第 1 轮测试。五轮矩阵和每个已执行轮次均默认折叠。
切换目标专利会清除上一案件的 `module9_batch` 和页面游标，恢复与继续均同时核验 investigation
和独立权利要求归属。fresh 第 1 轮仍以当前案件已持久化的模块七 D1/区别特征和模块八 I4-O 为
前置事实，缺少时明确提示先完成前置模块，不会借用旧案件结果。

概念画像中的 `text` 可以是解释发明点的完整复合语句，但检索式不复制整句。固定五组只绑定
画像顺序首个核心发明点，不因多个发明点复制同型线；确定性守门只在关键词确实能映射回概念
绑定的独立权利要求 feature ID 时放行，实现不维护实例专利专用词表。

模块三显示的 `inventive_point_features` 是检索级核心发明点，不是底层 feature 清单。
候选只有 1—2 项时保持原数量；不超过 3 项且技术目的彼此独立时分别保留；超过 3 项时按共同
技术目的或同一机构作用链归并为 1—3 项。归并后的每项绑定该组全部底层 feature ID，原始构件、

## GLM 连接预算

I2 向每个 GLM 直连候选发送专利正文或图片前，先进行不含鉴权和业务载荷的快速 HEAD 预检。
默认预检上限为 5 秒，失败即换线；通过预检的单次真实请求上限为 180 秒，整次模型调用共享
360 秒总预算。可通过以下变量调整：

```text
INVALIDITY_LLM_DIRECT_PROBE_TIMEOUT_SECONDS=5
INVALIDITY_LLM_DIRECT_ATTEMPT_TIMEOUT_SECONDS=180
INVALIDITY_LLM_TIMEOUT_SECONDS=360
INVALIDITY_I2_LLM_DIRECT_ATTEMPT_TIMEOUT_SECONDS=180
INVALIDITY_I2_LLM_TIMEOUT_SECONDS=360
```

后两项是 I2 专用覆盖；未设置时与通用预算保持一致。上述预算只防止坏线路长期占用任务；
只要健康线路仍在预算内生成，I2 会等待合法完整响应，
不会因固定短超时截断正常模型输出。通过 PM2 启动时，`scripts/http_run.sh` 的隔离
`env -i` allowlist 也必须透传这三个变量；否则服务会退回代码默认值，导致页面设置与实际
等待时间不一致。live I2 的 worker 外层 `max_attempts=1`：网络超时/探测失败不会把同一
多分钟调用重复三遍；模型已返回 JSON 但不符合查询守门时，才允许 I2 在同一 job 内根据
具体校验原因重新生成一次。

## Durable worker 并发

5209 默认在一个 API 进程内启动 2 个独立 `DurableWorker`，通过 PostgreSQL
`FOR UPDATE SKIP LOCKED` 和租约 CAS 并行领取互不相同的持久化任务。可在隔离环境文件中设置：

```text
INVALIDITY_WORKER_CONCURRENCY=2
```

允许范围为 1—4，超出时拒绝启动。每个 worker 使用独立 `worker_id` 和活动租约；停机时分别
释放正在处理的租约。模块实验室第六阶段使用持久化单篇比对批次，逐篇返回排队、执行、完成、
失败和已产生的 disclosure；页面断线或等待到期不删除后台任务。该批次只执行 I4-S，I4-C 与
I4-I 分别由第七、第十阶段显式启动。

旧前端直接创建、没有模块六批次 ID 的 I4-S 运行按最新 I3_FETCH 的
`candidate_filter_run_id` 恢复：只接受 `analysis_ready=true` 且正文/内容哈希完整的文献，已有
I4-S 复用最新 run，遗漏文献补建。仅更早且没有筛选血缘的数据使用时间连续性兼容兜底。

## 论文全文取得与证据升级

论文检索式与专利检索式使用不同的字段能力。arXiv、OpenAlex、Crossref 和公共 Web 不执行
IPC/CPC 过滤，因此 NPL 实际文本必须同时包含保护客体/类别和至少一个技术、机构或作用
特征。I2 不得把“客体 + 专利分类号”中正文只剩客体的查询复制到 NPL；I0 与 Portal 发送
`text` 时必须同时保留 `subject_terms` 和 `feature_terms`。复合来源会在 fan-out 前统一
校验一次，共同输入错误只显示一次，不再重复显示成四个 provider 的
`QueryValidationError`；校验通过后的真实来源故障仍分别展示。

模块四按以下顺序发现和取得非专利文献全文：

1. arXiv 的官方 PDF；
2. OpenAlex `best_oa_location`、`primary_location` 和其他 locations 中声明的 PDF；
3. Crossref link 中声明的 PDF；
4. 公共 Web 中通过安全校验的 PDF 或可核验正文。

元数据、摘要和 PDF URL 都只属于 `lead`。系统实际下载后还要校验 HTTP 内容类型和 PDF
文件签名，冻结原始字节并计算 SHA-256，抽取全文、渲染页面，才升级为
`retrieved_document`。之后公开日期资格和 I4-S 技术披露核验仍分别执行；只有全文、日期和
技术披露都满足要求时，文献才可进入律师的新颖性或创造性论证。律师页面会优先处理有直接
PDF 路由的论文，但明确区分“已发现 PDF 地址”和“已取得全文”。

本机 TUN fake-IP 环境只对 `arxiv.org`、`export.arxiv.org` 两个官方域名作精确兼容；其他
出版社和机构仓储仍必须通过公共 DNS 与 SSRF 守门。真实验证 run
`fd73a074-dbea-4a28-9b0f-c84246dda6de` 从 arXiv 取得 67,007 字符全文、4 张页面图和
SHA-256 `22b822fb3b0022e35a1b5156b47d599f4e5ba6810d92802624a2633c516e0bb2`。
该论文只用于验证取文能力，并非已核验的水枪对比文件；后续日期资格仍正确保持 unknown。

专利全文不以网页抓取代替正式数据源。智慧芽 P002 负责候选发现，EPO OPS 先按同一公开号
取回官方题录、XML 全文（覆盖时）和完整文献 PDF；只有 EPO 明确无同号内容/媒体时，才用
P002 原始 `patent_id + pn` 调智慧芽 P020。EPO 与 P020 的原始响应、身份映射、尝试顺序和
哈希分别审计。题录、metadata 或签名链接本身仍只是线索，只有真实 PDF/全文字节、MIME、
精确公开号、可解析页数和 SHA-256 均通过后才是 `retrieved_document`。日期资格和 I4-S
技术披露守门继续独立执行。

## 律师模块四与模块五的文献处理口径

- I2 运行时只能读取目标专利事实，不得读取无效决定书、决定书中的对比文件公开号或人为
  整理的答案术语。决定书样本只允许放在 `tests/fixtures/blind_benchmarks/`，并在查询和
  检索结果全部冻结后由 `scripts/evaluate_blind_retrieval.py` 评价命中名次；运行时源码
  禁止导入该目录。
- 首轮检索式保持短组合：发明机构精确线通常为保护客体/分类号加 1—2 个机构关系锚点；
  系统结构与变体线通常为保护客体加 2 个左右构件角色或关系锚点；名称摘要线只在概念可能
  出现在标题/摘要时使用。每条文字表达最多 3 个概念组，不把完整权利要求机械串成长 AND。
- 每条实际专利或 NPL 检索结果按供应商原始排序取前 10 篇；同一独立权利要求下相同文献可
  跨检索式去重，但不得用前 2 或前 5 等隐藏抽样。
- 每条检索的供应商原始前 10 篇先完整冻结，再由 `I3_CANDIDATE_FILTER` 在取文前清理：
  申请号相同、公开文本主号相同但 kind code 不同、可靠同族/稳定 ID 相同的记录合并为一个
  代表；只有题录足以证明技术客体与作用机理均明显无关的唯一代表才排除。信息不足、可能
  存在相同介质/能量、部件作用、操作关系或可类比机理、模型超时/失败时一律保留。
- 清理后全部唯一代表逐篇尝试取文，不得再作前 2/前 5 等隐藏截断；只取得题录、摘要或
  PDF 地址的仍是 `lead`。原始命中、合并关系、排除理由和每篇取文失败原因均单独展示，
  其他候选成功不能把整批显示为完成。
- 取得原始文件不等于可实体比对。I3-E 为同一内容哈希生成
  `readable-patent-v1` JSON/Markdown；EPO description/claims XML 可直接完成结构化，
  普通 PDF 必须覆盖全部页，扫描 PDF 必须逐页 OCR。只有 `analysis_ready=true` 的文献才
  逐篇运行 I4-S；标题、摘要和题录绝不作为全文替代。
- 模块五取文前会按带 kind code 的完整公开号查找同环境历史全文。只有
  原文字节数/SHA-256、可读化版本、JSON 哈希和全页状态现场校验全部通过时，
  才跳过 EPO/P020 与重复 OCR；旧标准化版本只从已验证原文在本地重建。不按
  标题、同族或公开号主号模糊复用。复用后仍重建当前候选谱系、重做日期核验，
  模块六仍对当前目标专利的特征实质重新比对，不复用历史特征序号或结论。
- I4-S 输出同时包含权利要求特征原文、披露状态、精确引文、位置、目标结构角色、对比文件
  结构映射、映射依据、结构证据、集成构件标记和全文候选结构排查概况。术语、零件数量或
  拆分方式不同，只要该特征实际相关的角色、流路/能量路径、连接拓扑、运动/状态或控制关系
  实质对应，即可构成结构等同；不适用于该特征的维度不得机械要求。只有功能或效果相同仍须
  降为不确定。
- 依靠工作过程才能推出的结构只能使用 `necessarily_implicit`，并必须保存三段闭合推导链：
  已明确公开的构件/关系 → 运行所需物理或机械条件 → 必然存在的目标角色/关系；同时说明并
  排除重力、外部泵、另一流道、固定件等与全文相容的合理替代路径。链条或替代路径分析不全
  时保持 `uncertain`。
- “全文复核后未找到该特征”只有在 `mapping_basis=none` 且已记录检查过的候选结构及其不能
  承担目标角色的原因时才使用 `not_disclosed`；目标术语、零件名称或完整复合语句未出现，
  不能单独推出未披露。材料不完整、结构含义模糊、证据冲突或无法判断使用 `uncertain`。
- 首轮结果已含至少两个高置信正向结构映射，或不超过五项的短权利要求中高置信正向结构
  映射达到 40%，同时仍有开放特征时，`structural-disclosure-v7` 只把开放特征送入一次整体
  结构复核。首轮理由若已承认候选构件的移动、旋转、开闭、流动、连接、传力、导电、传热
  或承压关系，却仅因名称/拆分不同否定，也会触发复核。真正的拓扑差异（例如导线相连但
  没有形成闭合回路）不会被该规则自动改判。
- 复核仅发送压缩后的机构上下文、证据窗口、最多八项最有结构对应可能的首轮开放项和不可
  改动的正向项，最多使用一张目标图、两张对比文件图；总预算 60 秒、单直连地址最多 40 秒。
  模型临时失败时保留首轮
  结果，同时明确记录 `structural_review_status=model_error`，本篇不得进入后续实体聚合；
  模块六 I4-S 批次只自动补跑一次，仍失败则以 partial 收口。普通不相关文献和单特征结果不增加
  第二次调用。

## I3 取文前候选清理

律师模块四不会再把每次检索的原始前 10 条不加区分地全部下载。它先创建
`I3_CANDIDATE_FILTER`：

1. 原始命中和排名继续完整保留；
2. 同一申请、同一公开文本的不同 kind code、可靠同族或稳定 ID 合并为一个代表；
3. GLM-4.6V 依据 I2 的保护客体、发明点和整体机理，批量标记相关、不能确定或明显无关；
4. 只有“没有任何相关客体、介质/能量、部件作用、操作关系或可类比机理”且高置信的候选
   才不取文；
5. 题录不足、模型漏项、网络超时或判断不完整均保留，清理后的全部唯一代表逐篇取文。

律师页逐条显示“进入取文”“明显无关未取文”或“同申请/同版本已合并”，并汇总原始数、
重复数、排除数、实际取文数和预计节省的取文请求。技术页可直接选择
`I3_CANDIDATE_FILTER`；fixture 单元验证脚本现覆盖全部 12 个底层模块。live 取文只接受
同案持久化的 `candidate_filter_run_id + candidate_id`，浏览器不能重新提交候选题录；
清理输出同时保存合同/身份/语义规则版本、输入哈希、决定哈希、模型 prompt 哈希和总审计
哈希。当前这条完整衔接已经用于律师模块四和完整 I0；I0 按同一“两阶段发现后统一清理、
再取文”合同执行，不能用仅存在模块代码但发生在取文后的记录冒充 I3-F 完成。

正式 `ConfiguredEvidenceGateway` 明确拆分 `discover` 与 `retrieve`；仅为旧 fixture 或注入
测试保留的单阶段 gateway 会在审计中标为 `prefetch_filter_applied=false`，不得通过 live
完整性门。live 报告还必须证明同轮 I3-F 已成功、输入/输出哈希完整且完成时间早于 I3-FETCH。

## I2 原子关键词规则

- 可执行检索词是单一技术概念，不是说明句或多个概念的拼接。
- `中间位置、选择性联接`会拆成`中间位置`和`选择性联接`；短召回默认使用信息量更高的
  `选择性联接`，需要位置限定时才另加`AND 中间位置`。
- `位置选择性联接装置`这类表达单一完整技术概念的术语可以整体保留，主要用于长精确线
  或同概念受控扩展。
- 一个 OR 组只保存同一原子概念的原词和可追溯等价词；不同位置、动作、构件关系必须使用
  不同 AND 组。每组最多 5 个成员，截断时优先保留已有跨语言对应词。新模型结果与同源历史
  画像都经过同一确定性守门。
- 系统结构召回同时保留“客体 + 两个构件”的组合线和有界的“客体 + 单构件”分线；复合
  常见构件在宽召回线缩短为可检索的部件词，并保留原词及中英文普通等价词，例如
  `压力罐 -> 罐/储液器/tank/reservoir`、`带有阀导管的阀 -> 阀/valve`。这些等价词只用于
  检索，不预先证明模块五的结构披露。
- 分类角色不明时不再为同一发明点机械复制全部分类号；保留首尾两个代表分类，释放查询
  预算给不同构件与控制链结构。每条实际 P002 查询仍各自冻结前 10，命中名次不得跨同角色
  查询累加。

## I4-S 结构等同与分散原文证据

模块五比较的是完整机构，而不是词面：名称、缩写或零件拆分方式不同，应回到构件角色、
连接拓扑、运动/状态、介质或能量路径和整体工作作用。复合关系可以由同一文献不同段落共同
证明，但每个构件、集合成员和关系段都必须能在当前冻结全文中逐字回溯；只有上位类别词或
相同用途不能确认披露。

完整全文及附图已经核查且明确没有对应开口、通道、定位构件或位置关系时，输出
`not_disclosed`。如果只是没有出现目标专利使用的名称、候选结构仍可能以其他形式存在，继续
输出 `uncertain` 并提示复核。

对于流体阀，只有同一对比文件同时可回溯入口—阀座—出口流路、可移动闭合件、封紧阀座的
关闭状态和离开阀座后的通流状态，系统才会把集成的阀座/流路、阀芯/压柱映射为目标的阀导管、
阀杆、阀塞及开闭位置。该映射不会顺带证明轴线、位置选择性联接或中间位置。当前测试规则
版本为 `structural-disclosure-v50`。OCR 把同一原文段落拆成空行块时，只允许在同一文献内
合并最多 12 个相邻块形成可回溯证据窗口，不允许跨段跳选或跨文献拼接。

对于配方数值，质量份/重量份与重量百分比不能脱离计量对象直接互换。只有同一组分明确以
整个组合物为用量基准、区间相交、原文可回溯且没有树脂/溶剂等其他分母时，才将两种写法
视为含量的等价表达；存在其他计量基准时继续标记为不确定。

`skipped_feature_resolved`。重复文献可复用旧 FETCH/QUALIFY/I4-S，但必须同时匹配不可变全文
哈希、文献版本、日期资格 revision、矩阵输入摘要以及当前 I4-S prompt/rule。
